# 当前权限入口移至输入框验收

- Issue #20；spec 0111 的 2026-10-27 呈现调整。
- 用户要求：顶部右侧只保留文件浏览且靠右，权限／信息入口紧邻输入框加号。
- 使用 frontend-design 的既有设计体系优先原则：复用信息 SVG、深色 token 和现有警示语义，不增加图标库或权限功能。

## TDD 与实现

1. 先在 App unit 断言权限不在 header、位于 composer-actions、前一个控件为附件加号；旧代码实际失败。
2. 手机 Chromium 先断言 header 只有菜单和文件两个按钮；旧代码实际返回三个控件，测试失败，再开始重排 DOM。
3. 按钮及弹层内容、ARIA、未知／Full Access 警示、外部点击、Escape 和设备／会话切换时关闭均保留。header 仍是 52px，两行标题与路径可用宽度增加；没有文件 capability 时不制造入口。
4. 弹层用 fixed 定位从按钮上方展开，横向限制到 viewport 内；视觉 viewport、resize／scroll 和输入区 ResizeObserver 更新定位，监听在关闭／unmount 时清理。保持原 composer／历史折叠 overflow，不为弹层放开所有裁剪。
5. 缩窗测试复现桌面原有 min-height:620px 将 composer 推出 450px 窗口，导致弹层中心无法命中。仅已连接页面 min-height 归零，登录页规则不变。新增中心 elementFromPoint 命中断言，不只依赖截图或 boundingBox。
6. 320px 下六个控件同时出现的测试又复现模型入口小于 44px、图标重叠。模型入口设置 44px 下限；最拥挤状态压缩内部间距并去掉装饰 chevron，保留强度／速度图标及完整可访问名称。
7. 快速桌面→手机 resize 时，原横向 padding 动画暂时把操作栏挤到 271px；只动画上下 padding，稳定横向空间，保留原历史折叠动画。测试同时验证按钮间距、图标位于控件内及操作栏无 overflow。
8. 全量 unit 发现上一版 README 加功能后超过现有 100 行约束；合并两条相关功能描述并补充入口位置，保留测试约束，不放宽断言。

- 320／390／1280px，44px 点击区域、文件靠右、加号与权限相邻、超长标题／路径／模型名。
- 原生权限弹层可实际命中、向上展开、缩小到 450px viewport 后仍可见且在按钮上方，草稿不丢。
- 运行中＋编辑队列＋停止＋发送并存时所有控件不重叠，强度和速度图标不越过模型入口边界。
- 原有外部点击／Escape／开关、文件浏览、模型面板、历史折叠／恢复、软键盘 viewport 与 streaming 回归。
