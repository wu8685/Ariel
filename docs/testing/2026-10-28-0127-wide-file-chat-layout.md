## 实际 red → green

1. 1280px 浏览器先运行三列交互用例：原实现打开文件后找不到可见的“发送消息”输入框，真实 red。
2. 为独立菜单状态先写 hook 单测，再实现宽屏 dock／窄屏 drawer 的状态分离、选择会话只关闭 drawer、断点监听及清理；宽屏不渲染遮罩，实际可见性控制 inert／aria-hidden、设备菜单和现有未读刷新条件。
3. 三列专项加入真实新建能力后，280px 侧栏的品牌文字截断断言 red。仅宽屏移除重复关闭按钮（仍保留主会话菜单开关），压缩品牌字号／Logo／间距；全部实际操作仍保持 44px，品牌文字完整。
4. 新增 IME 浏览器用例：compositionstart 后 Enter 仍发送一次 turn.start，期望 0、实际 1，red。增加组合态双重保护；跨断点时暂不隐藏正在组合输入的会话，compositionend 后再转入文件与焦点，正文不卸载、草稿不丢失。
5. 新增长文重排用例：打开文件后首个可见历史项从 long-7 变成 long-3，red。用 ResizeObserver 检测实际列宽变化，在浏览器布局事件覆盖旧位置前保留原阅读锚点和跟随意图，不新增轮询。
6. 再覆盖靠近历史底部的情况：最小化后 long-34 变成 long-42，red。修正基于浏览器实际钳制后的 scrollTop 恢复锚点，不假设重排前后 scrollTop 相同；中间与近底部场景均 green。测试等既有 header 收起动画结束后才取稳定锚点，不放宽位置断言。
7. 完整回归发现宽→窄切换后，一行文字的 composer 截图从 94px 高变成 118px：原 resize handler 在 React 布局提交前按旧列宽计算 textarea 高度。本次将实际布局模式、菜单和文件展开状态纳入提交后的重算，保留原手机截图并增加一行输入高度断言，green 后原图通过。
8. 新增实际 Tab 键路径断言：文件引用 footer 后不能到达右侧会话菜单，red。把文件组件在 DOM 中移至会话之前，使键盘顺序与左至右视觉顺序一致，不增加 DOM 副本；原文、Diff 与模型组件仍原地挂载。
9. 新增历史阅读状态下的引用断言：引用后仍找不到可见 composer，red。显式引用时恢复输入区并聚焦，宽屏文件继续打开；普通最小化仍保留历史位置，不因此自动回到最新。
10. 完整 Chromium 回归捕获快速缩窗的中间帧：viewport 已变为窄屏，React 尚保留宽屏 class，操作栏仅剩 88px 而控件需 232px。新增固定 JS 断点快照的确定性用例，主会话宽度期望 320px、实际仅 40px，red。用原生 `@media (min-width: 1200px)` 限制宽屏 CSS，修复中间帧；新用例和既有模型设置跨宽度用例分别重复 5 次均通过，不增加等待或放宽断言。
11. 原生媒体约束又使 IME 跨断点用例 red：在 JS 收到断点事件前隐藏会话会使浏览器 blur，从而过早结束组合态。现在在组合输入开始时即标记工作区，但仅窄屏 CSS 使用此标记，确保缩窗中间帧也不隐藏输入框；宽屏正常组合输入时文件仍可见。该轮在修复时触发 Vite HMR，另有 Mermaid fixture 停在同步态，故不作为最终完整回归结果；后续冻结产品代码后重新验收，不据此宣称 Mermaid 已修复。
12. 冻结后完整回归为 151／152，Mermaid 与 IME 均通过，唯一失败为普通输入缩窗后的文件 Tab 焦点：CSS 已先把焦点移到 body，旧迁移分支只识别会话内焦点。补充 body 分支恢复到当前文件 Tab，仍不抢占弹层中的焦点；保留原严格聚焦断言。

## 行为与资源

- 1200／1280／1440／1920px 三列几何；1024／1199px 独占文件；320／390px 既有手机行为继续回归。
- 宽屏可继续编辑、发送 fixture 消息、收到增量；引用只显式加入上下文并保留原草稿，文件保持打开。切换主会话后原文件仍可读，引用不能跨 thread。
- 侧栏手动收起偏好与抽屉状态分离；跨断点不出现意外遮罩；主会话内 Escape 不收起文件，文件内 Escape 沿用原语义。
- 420px 高短屏中引用 footer／正文／composer 均可操作；各区独立滚动；最小化回收全部文件列空间。
- 多模式／Tab／刷新恢复、150 Tab 的按需读取与有界正文缓存仍纳入回归；布局变化不创建新 socket／watch，不重复读取文件，不重建主会话或发送内容。
- 侧栏加入真实不可访问属性后，13 项既有 App 单测原先直接调用已关闭抽屉内控件。本次将这些侧栏业务单测明确置于宽屏 dock fixture，保留所有业务断言；手机抽屉开闭及隐藏控件的不可访问性由浏览器覆盖，不取消产品隔离。
- 两项文件安全恢复 fixture 亦需在独立会话历史自动恢复后显式打开抽屉才能检查列表；文件未恢复、零额外正文读取、原记录清理等断言不变，不为测试撤销 aria-hidden／inert。
