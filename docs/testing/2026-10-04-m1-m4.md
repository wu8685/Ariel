# M1–M4 本地验证记录（2026-10-04）

## 环境与范围

- macOS 本机；Codex Desktop `26.930.31730`、内置 CLI `0.160.0`。私有 IPC 只对这一配对放行。
- 所有会产生 turn 或文件变更的测试均使用 `cmd/probe fixture create` 新建的隔离临时 workspace；不对业务会话做写测试。fixture manifest 留在 `.local/`，不纳入版本控制。
- Web 由本地 Relay 提供，使用同机浏览器验证桌面链路；这不是物理手机或跨机器网络验收。

## SDD / TDD 证据

实现前分别写入 `docs/specs/0003`（M1）、`0004`（M2）、`0005`（M3）、`0006`（M4）。新增行为先有失败测试再修正：权限请求卡片/响应、Desktop 连续健康失败、Web 前台恢复、运行中历史超限、列表误带历史、敏感输入禁用等，都先记录了 red，再实现 green。Go、协议和 Web 的自动测试覆盖这些路径；单测不替代真实 Desktop 验证。

## 真实 Desktop 隔离验证

| 场景 | 观察到的结果 |
| --- | --- |
| 未加载历史自动接续 | Web 选中 fixture 后，Desktop 自动打开原 thread；Agent 找到原 owner，threadId 与 workspace 保持一致，随后可发送、实时显示并按 exact turn 停止。 |
| 命令审批 | 使用只读 sandbox / on-request 的隔离 turn 触发 `/usr/bin/true`。Web 单次允许后执行完成；第二次同命令仍重新请求批准，未形成永久规则。拒绝并停止后，独立历史核对为 interrupted。 |
| 补充问题 | 两个问题分别提交选项和自由文本；owner 快照精确回显，独立持久化历史确认完成。双客户端不同答案竞争说明单独 `ok` 回执不足以判断成功，生产响应因此再核对精确回显。 |
| 文件变更审批 | Web 卡片显示目标绝对路径和 diff。允许后，隔离目录出现内容为 `approved\n` 的 9 字节文件，SHA-256 与预期一致；另一个 fixture 在 Web 拒绝后文件不存在，原 turn 独立历史为 completed。 |
| 恢复 | 运行中的本地 Relay／Agent 分别重启后，Web 在同一页面保留设备和 thread 选择并自动重新订阅；旧视图清空，新快照接管。未完成请求不重发。 |
| 发送身份关联 | 隔离 fixture 证实原生 `userMessage.id` 与 `clientUserMessageId` 不同，而 `userMessage.clientId` 与本次提交 ID 一致。生产 Agent 现于原 owner 快照中核对 `turnId + clientId + 文本` 后才报 accepted；缺证据返回 unknown。 |

## 自动化结果

- `go test ./...`：通过。
- `go test -race ./...`：通过（后续变更须重新运行）。
- `go vet ./...`：通过。
- `web/npm test`：4 个测试文件、12 个测试通过（后续变更须重新运行）。
- `web/npm run build`：通过；TypeScript 声明从 `protocol/v1.schema.json` 生成。
- 补充边界单测：Relay／Agent 双向 ping 对半开连接做有界剔除；单个 owner follower 失效发送 `RESYNC_REQUIRED` 并可重新 attach；运行中历史超限发送 `HISTORY_TOO_LARGE` 而不发送大帧。

## 尚未完成的真实验收

1. 权限请求：`item/permissions/requestApproval` 的原生 schema、Desktop follower IPC、当前请求指纹、最小单轮 grant、拒绝及 Web 卡片有单测；但本机 `codex features list` 显示 `request_permissions_tool` 为 `under development / false`，隔离 Desktop turn 直接回复工具不可用，因而没有原生待审批样例。不可把协议单测称为真实通过。未擅自修改 Desktop 全局 feature 或启动参数。
2. 物理手机：没有操作用户手机的连接或设备；同机浏览器测试不冒称手机验收。README 给出了可信局域网启动命令和安全边界。
3. Desktop 进程退出／重启：Agent 的 IPC preflight 与连续两次健康失败状态机有测试，真实 Agent 在当前 Desktop 下成功接入；未为了测试而退出承载业务会话的 Desktop。
4. 外部 Desktop 与 Ariel 在同一瞬间发起 turn：生产 Agent 有线程级串行入口、live idle 预检，并以原生 `userMessage.clientId` 做发送归属核对；尚未做双客户端精确同时提交的真实压测。竞态中缺乏确证时返回 unknown，而不是声称本次已发送。

以上限制不扩大产品范围，也不隐含自动批准、离线排队或公网安全保证。
