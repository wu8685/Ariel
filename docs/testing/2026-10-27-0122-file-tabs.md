# 0122 第一阶段：多文件 Tab 验收

- 日期：2026-10-27。
- 规格：[0122 Approved](../specs/0122-minimizable-file-viewer.md)；Issue #44。
- 范围：文件 Tab 工作区；没有实现侧边新对话、fork 或新通信协议。
- 环境：jsdom 单测、Chromium 手机 viewport／touch 模拟与桌面 viewport。不是物理 iPhone／Safari 验收。

## 1. 用户可以使用的功能

- 从修改文件卡片、消息中的文档引用、工作区文件树和 Markdown 相对文档链接打开多个文件。
- 宽屏左右并排，手机上下分区；文件保持打开时仍能编辑主会话草稿。
- 文件标签无固定数量上限，横向滚动和可搜索／分页的全部标签；相同来源去重。
- 整体收起／展开、切换、关闭相邻标签，保留原版／阅读／Diff、滚动和可重新确认的选区。
- 文件引用仍显式操作并校验来源会话；主会话切换后可读旧文件，不能把旧引用悄悄转交其他 thread。

## 2. Red → Green 证据

| 用例 | Red | Green |
| --- | --- | --- |
| 工作区入口与并排 | 旧界面无“文件标签”tablist，390px 浏览器断言失败 | 320／390／1280px 全流程通过，composer 可编辑且无横向溢出 |
| 模型与状态 | 新测试先于模块，初次无法解析模块 | 无固定 Tab 上限、缓存、乱序、关闭／清理、重试、引用来源均通过 |
| Markdown 滚动恢复 | 浏览器切回时实际 scrollTop 为 0，期望 170 | 等待阅读内容／图片会话准备后恢复，不让准备占位状态覆盖锚点 |
| 被淘汰的 Diff | source 重读后“查看 Diff”误禁用 | Diff 存在性与正文驻留分开；激活后按来源重读 |
| 主会话文本选择 | 在主会话选字导致已捕获文件选区丢失 | 仅处理文件内的选区，不干扰并排主会话 |
| 历史重写 | 缺少按来源会话清理方法 | 仅清理被重写会话的标签，其他会话文件保留 |
| 键盘关闭 | Delete 后焦点落到 body | 焦点回到相邻 Tab；收起可返回主会话输入框 |
| 后台迟到与容量 | 单资源预算下后台 A 响应淘汰正在看的 B | 优先淘汰非激活资源，迟到响应不能迫使当前文件重读 |

150 个文件的真实浏览器用例通过原文档引用入口批量打开：保留 150 个标签，仅一个正文，初次仅一次激活文件读取、一次 thread watch；全部列表只渲染 40 项，搜索、切换和键盘导航通过。消息内原有的 24 个引用保护阈值没有放松，fixture 用不同消息分别提供来源。

## 3. 资源与安全检查

- Tab descriptor／阅读锚点不保存全文，选区只存 source offsets；正文和 Diff 共用 8 MiB／10 项 LRU。
- 收起和后台 Tab 不挂载正文／Markdown／图片；图片 session 卸载释放，缓存淘汰只在激活目标时按需恢复。
- 每个读取绑定独立 Tab identity／generation；晚到结果不抢焦点，不重开关闭标签，不复用旧 epoch。
- 不增加 socket、follower、thread 创建或后台轮询；保留已有能力 flag、路径／SHA／来源校验。
- 全程使用隔离 WebSocket fixture；原生大帧回归使用隔离 Unix IPC／Agent／Relay fixture，没有向真实用户会话发送内容。

## 4. 回归结果

- `npm test`：330 项 Web 单测通过。
- `npm run build`：通过；沿用已有大 chunk 提示，无新增依赖。
- `GO111MODULE=on go test ./...`：通过。
- `npx playwright test`：105 项通过，包括真实隔离 Relay／Agent／大帧与 Passkey 流程。
- 最终缓存保护改动后，文件专项重复两轮（34 项）通过；完整浏览器回归结果同时涵盖其余交互。
- 固定截图：新增 320／390／1280px 多文件工作区；核对并更新原阅读／Diff／引用布局基线，保留行为与几何断言，不只更新截图。

并发回归还复现了测试基础设施竞争：Passkey fixture 重建共享 `web/dist` 时，大帧 fixture 暂时读到目录列表，导致找不到连接码输入框。Passkey 构建已迁入其私有临时目录，两项并发复跑及全量回归通过；没有修改生产认证／连接逻辑。
