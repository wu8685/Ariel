# 0122 第一阶段：多文件 Tab 验收

- 日期：2026-10-27。
- 规格：[0122 Approved](../specs/0122-minimizable-file-viewer.md)；Issue #44。
- 范围：文件 Tab 工作区；没有实现侧边新对话、fork 或新通信协议。
- 环境：jsdom 单测、Chromium 手机 viewport／touch 模拟与桌面 viewport。不是物理 iPhone／Safari 验收。
- 布局更正：用户验收后明确要求全屏文件／最小化会话二选一；以下第 2–4 节保留初版开发证据，旧分屏结论由第 6 节更正验收取代。

## 1. 用户可以使用的功能

- 从修改文件卡片、消息中的文档引用、工作区文件树和 Markdown 相对文档链接打开多个文件。
- 文件展开时独占内容区，最小化后显示会话；所有屏宽均不分屏，草稿与后台订阅保留。
- 文件标签无固定数量上限，横向滚动和可搜索／分页的全部标签；相同来源去重。
- 整体收起／展开、切换、关闭相邻标签，保留原版／阅读／Diff、滚动和可重新确认的选区。
- 文件引用仍显式操作并校验来源会话；主会话切换后可读旧文件，不能把旧引用悄悄转交其他 thread。

## 2. Red → Green 证据

| 用例 | Red | Green |
| --- | --- | --- |
| 工作区入口与并排 | 旧界面无“文件标签”tablist，390px 浏览器断言失败 | 320／390／1280px 全流程通过，composer 可编辑且无横向溢出 |
| 模型与状态 | 新测试先于模块，初次无法解析模块 | 无固定 Tab 上限、缓存、乱序、关闭／清理、重试、引用来源均通过 |
| Markdown 滚动恢复 | 浏览器切回时实际 scrollTop 为 0，期望 170 | 等待阅读内容／图片会话准备后恢复，不让准备占位状态覆盖锚点 |
| 被淘汰的 Diff | source 重读后“查看 Diff”误禁用 | Diff 存在性与正文驻留分开；激活后按来源重读 |
| 主会话文本选择 | 在主会话选字导致已捕获文件选区丢失 | 仅处理文件内的选区，不干扰并排主会话 |
| 历史重写 | 缺少按来源会话清理方法 | 仅清理被重写会话的标签，其他会话文件保留 |
| 键盘关闭 | Delete 后焦点落到 body | 焦点回到相邻 Tab；收起可返回主会话输入框 |
| 后台迟到与容量 | 单资源预算下后台 A 响应淘汰正在看的 B | 优先淘汰非激活资源，迟到响应不能迫使当前文件重读 |

150 个文件的真实浏览器用例通过原文档引用入口批量打开：保留 150 个标签，仅一个正文，初次仅一次激活文件读取、一次 thread watch；全部列表只渲染 40 项，搜索、切换和键盘导航通过。消息内原有的 24 个引用保护阈值没有放松，fixture 用不同消息分别提供来源。

## 3. 资源与安全检查

- Tab descriptor／阅读锚点不保存全文，选区只存 source offsets；正文和 Diff 共用 8 MiB／10 项 LRU。
- 收起和后台 Tab 不挂载正文／Markdown／图片；图片 session 卸载释放，缓存淘汰只在激活目标时按需恢复。
- 每个读取绑定独立 Tab identity／generation；晚到结果不抢焦点，不重开关闭标签，不复用旧 epoch。
- 不增加 socket、follower、thread 创建或后台轮询；保留已有能力 flag、路径／SHA／来源校验。
- 全程使用隔离 WebSocket fixture；原生大帧回归使用隔离 Unix IPC／Agent／Relay fixture，没有向真实用户会话发送内容。

## 6. 全屏／最小化更正验收（Issue #46）

用户更正后的 spec 先于实现更新。先修改 Chromium 用例并实际运行 390px 验收，旧版本在 `expect(composer).toBeHidden()` 失败：实际输入框仍然可见，复现了分屏行为。随后删除左右／上下 grid，改为文件独占内容区、会话不可见且 `inert`／`aria-hidden`，但不卸载会话或将其高度归零。

- 320／390／1280px 几何断言：文件从 (0, 0) 开始，占满内容区全部宽高；输入框不可见，不允许聚焦隐藏输入框。
- 最小化／Escape／关闭最后一个 Tab 后恢复会话；最新位置回到 composer，阅读历史时回到 transcript，不强迫回到底部。
- 多文件仍保留模式、选区和阅读位置；短屏引用 footer 可操作，引用后回到会话且草稿保留。
- 隐藏期间 fixture 推送新回复，后台正常收到；最小化后显示最新正文，历史 scrollTop 保持不变，仍只有一个 cache watch，无额外订阅、历史加载或发送。
- 已核对全屏文件、阅读模式与 Diff 的固定手机／桌面截图并更新基线；150 Tab、图片 lazy 读取、精确引用、退出后的资源卸载继续通过。
- 全量结果：330 项 Web 单测、107 项 Chromium、Go 全量与生产 build 通过；文件专项 19 项通过。

本次为 Web 布局更正，无协议／native API／Chilling 依赖变化。物理 iPhone／Safari 与实际软键盘仍待用户复验；Chromium 手机 viewport／touch 不代表物理设备测试。

## 7. 按需引用栏（Issue #48）

用户明确要求默认收起“引用到会话”，选中文件内容后再显示。先修改 spec，再运行新增单测和 390px Chromium 用例：旧版本因为仍有一个 footer（期望 0）失败。另补充清空所有原生 Range 的失败用例，复现取消选区后旧捕获状态仍保留，再增加选区归属与引用栏焦点保护。

- 原文／Markdown 无捕获选区时不渲染 footer，正文直接延伸到底部；非空选区后显示。320／390／1280px 同时断言正文高度减少量等于引用栏高度、两者不重叠；取消后原高度恢复。
- 真浏览器 touch tap 取消、折叠光标选区、阅读模式切换、引用成功均通过；不额外读取文件、创建订阅或发送消息。
- 无法映射的文件选区保留原有纠错提示与禁用操作；引用来源不匹配时仍禁用。SHA 改变会清除旧选区及错误栏；Diff 不显示引用栏。
- 区分当前原生选区与跨 Tab 恢复的捕获选区，避免空 selectionchange 清空恢复状态；聚焦引用按钮时保留待提交片段。跨 Tab／最小化恢复、图片与原有精确引用回归继续通过。
- 全量结果：334 项 Web 单测、110 项 Chromium、Go 全量、生产 build 通过；23 项文件专项通过。新增默认／选中两种状态在三种宽度的截图基线，既有无选区截图按新增阅读空间更新并核对。

本轮仅实现和测试 Web 调整，不部署／重启线上或本机 Agent；不变更协议、缓存或 Chilling。物理 iPhone／Safari 的选区手柄行为仍待用户复验。
