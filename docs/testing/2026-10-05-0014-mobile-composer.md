## 浏览器实测（隔离 Mock，不是物理手机）

- 在 390×844 的真实浏览器视口，空草稿输入区 44px；实际按 Enter 后内容为 `first\n`，会话没有新消息；点蓝色发送按钮后，Mock 会话收到带换行的消息，输入区清空。
- 十个显式行时输入区固定 212px（24px 行高 × 8 + 20px 上下内边距），内容 `scrollHeight` 260px、`clientHeight` 212px，垂直滚动可用；修复后光标位于末尾时 `scrollTop` 为 48px，最后一行可见。无显式换行的长文字也随自动折行增高；删除至短句后回到 44px。
- 发送按钮为 44×44px，位于 844px 视口之内；对话滚动区仍有 546px 高度，页面没有横向溢出。
- 1280×720 宽屏下，实际按 Enter 仍由 Mock 会话收到消息；临时浏览器视口已复原，隔离 Relay、Mock Agent 和测试标签页已关闭。

## 物理手机复验

2026-10-05，用户在真实手机 Safari 上打开隔离 fixture，并在输入框内输入至第 9 行；确认软键盘 Return 只换行、没有发送，会话历史仍保持原有 3 个 turn。输入框到第 9 行后不再长高，可在框内上下滚动。随后用户补充：**输入框获得焦点后，界面被放大，蓝色发送按钮大半超出屏幕右边界**。因此原先的“按钮可见”仅适用于未聚焦状态，不能算作设备侧通过。

针对手机输入框原有 `font-size: 14px`，先新增聚焦防放大回归测试，观察到 1 项预期失败；再把手机输入字号调整为 16px，保持 24px 行高、八行 212px 上限与 44px 按钮。Web 全量测试 65/65、构建通过。在 390×844 本机浏览器中，聚焦并输入九行后，输入框 `clientHeight=212px`、`scrollHeight=236px`，按钮右缘为 377px，文档 `scrollWidth=390px`，无横向溢出。生产 8080 入口已提供包含该 CSS 的新构建。

修复后的真实手机 Safari 聚焦复验、按按钮向真实 owner 发送、失败时草稿保留和键盘弹出后的不同屏幕尺寸仍需单列核对；本节不以本机浏览器布局通过推定设备侧通过。
