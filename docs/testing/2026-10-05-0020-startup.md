## Red → green

先写 `internal/startup` 测试，实际运行时因启动模块／脚本不存在而编译失败；随后实现私有配置、双模式参数、构建范围、PIN／token 复用、URL 校验、代理绕过和受管 PID 检查。另写 Agent 握手就绪回调测试，先观察 `OnReady`／`OnNotReady` 不存在的编译失败，再接入握手成功／断线撤销的状态文件。后续又先复现并修复：换凭据被静默忽略；外部模式切本机时误复用远端口令；PID 复用需比较启动时间；同进程回滚时已退出子进程短暂成为 zombie；Agent-only 的 `stop` 不应涉及 Relay；符号链接私有目录会把凭据写出仓库；构建／子进程不应继承无关的 Ariel 凭据环境变量。

自动覆盖配置文件 `0600`、私有目录 `0700` 且拒绝符号链接、长口令与六位码独立及持久复用、从外部模式转本机模式不复用外部口令、配置与构建环境不泄漏凭据、外部 `wss` 默认要求和明文 `ws` 显式开关、非法监听地址、端口冲突、代理 `NO_PROXY`、受管 PID 精确身份、脚本入口、显式 `show-pin`、启动失败回滚和双模式停止边界。测试 fixture 的所有进程、端口与目录都是隔离的。

## 当前 LAN 服务切换

先在旧服务仍运行时，私下将其长口令、六位码与稳定设备 ID 导入新脚本配置，核对导入值与原值相同；脚本对被旧 Relay 占用的端口如预期拒绝接管。随后只定点停止旧 Relay／Agent 进程，再执行 `./scripts/ariel.sh up`。新版同一 LAN `8080` 启动成功，`status` 显示 Relay 在线与 Agent 握手就绪；已鉴别的只读 `device.list` 返回原设备在线且 `codexReady=true`，`thread.list` 接受请求并返回 50 条索引。没有调用发送、停止 turn、审批或补充回答。

Relay 重启使既有浏览器 session 失效，手机可能需要重新输入**原六位码**。物理手机尚未完成切换后的重新登录与历史显示复验，保持项目 TODO 未勾选。脚本不提供开机自启或公网部署；外部 `wss` Relay 真实 TLS 联调仍未实测。凭据、真实会话正文和私人路径未写入本记录或提交。
