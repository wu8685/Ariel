## 1. Red → Green

先新增真实 Chromium `page.reload()` 用例并运行。旧实现打开文件、最小化后刷新，找不到“展开文件工作区（1 个文件）”，5 秒断言超时，确定性复现现场丢失。新增元信息单测先以缺失模块失败，再实现存储与恢复。

| 行为 | 验证结果 |

| 刷新恢复 | 320／390／1280px 实际刷新，恢复两个 Tab 的顺序与激活项、Markdown 模式、650px 滚动；原文选区与 400px 位置恢复，Diff 500px 位置恢复 |
| 最小化与数量 | 最小化后刷新零正文请求，展开才读；150 Tab 刷新后不丢失，仅读取激活文件，只有一个正文，不增加 per-file watch |

额外回归定位到历史修改文件列表与恢复读取的竞争：旧逻辑在列表响应后再次淘汰刚读取的当前文件，同一文件一次刷新会出现两次正文读取。补上失败单测和真实浏览器请求计数，修复为仅淘汰查询前仍驻留的旧资源，且不把已完成的同一来源变更当成新事件。该 fence 只保存资源版本数字，不额外持有正文；真正的新文件变更失效语义保留。

## 2. 资源与恢复边界

- 独立 key `ariel.file-workspace.v1`，仅当前标签页 `sessionStorage`，1 MiB／7 天；正文与 Diff 继续共享 8 MiB／10 项内存 LRU。
- 不保存浏览器原生 Range、菜单状态、图片 Blob／外部图片授权、运行中请求或 owner receipt，不重放引用／发送／创建会话。
- source offsets 由重读并核验 SHA 的正文重建；Diff 的本地 128-bit 指纹只用于阅读位置变化检测，不是授权或执行证明。原来源和后端路径／版本核验仍执行。
- 退出／手动设备切换／授权撤销／确认的 epoch 变化删除记录；临时断线／原地续登录保留，核验后重读。
- 文件变化不会被旧选区掩盖；文件错误局限在对应 Tab，可重试或关闭，不产生登录循环。

## 3. 自动化结果与未验项

- Web 单测：349 项通过。
- `npm run build`、`GO111MODULE=on go test ./...` 通过，保留已有大 chunk 提示，无新增运行依赖。
- 完整 Chromium 回归：最终 125 项通过；刷新专项 12 项通过。
- 新增 320／390／1280px 刷新后阅读截图，逐张核对 Tab 栏、正文换行、全屏边界；行为断言同时验证位置、模式和读取次数，不只比截图。

一次完整回归中，旧阅读用例在图片占位改变有效滚动范围时出现 427px／413px 的差异。原断言未考虑规格允许的范围 clamp，现同时读取实际 `scrollHeight - clientHeight`：位置仍有效时必须完全相同，原位置超出新范围时必须恰好等于新上限，任意其他漂移仍失败。三种宽度各重复 5 次（15 项）通过；不等待所有离屏图片强制加载，也未修改图片 lazy 实现或放宽像素容差。

全部浏览器写请求使用隔离 fixture，没有向真实 Codex 业务会话发送、停止、审批或修改文件。没有改变私有 Codex 集成接口；原兼容性证据继续适用。物理 iPhone／Safari、真实系统强杀／内存回收的最后一瞬间保存仍未验证；不把 Chromium 手机 viewport／touch 模拟冒称物理设备验收。本轮未部署。
