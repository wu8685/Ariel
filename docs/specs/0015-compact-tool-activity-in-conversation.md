# 0015：工具活动默认折叠，按需查看每段调用

- 状态：Approved（用户于 2026-10-05 确认修订版）。
- 来源：手机会话中大量重复的“系统 / [mcpToolCall 项目]”挤占正文。用户先要求压成一行状态，后明确希望像 Codex App 一样：一组对话之间的 tool call 等消息默认收起，主动点击后才展开每段调用。
- 范围：手机与桌面共用的会话正文投影；原 Codex owner、审批卡片、发送语义和 [0013](0013-paged-history-and-large-owner.md) 的分页／容量边界不变。此规格取代原 Draft 中“历史工具过程永久不展示”的提案。

## 输入、输出与用户行为

1. 用户消息、Codex 正文、计划和明确的交互结果继续按原顺序显示。相邻的已知工具活动 item 在同一 turn 内合并为一条紧凑摘要，默认折叠，不再反复出现“系统 / [mcpToolCall 项目]”卡片。正文消息或交互结果将相邻活动分成不同组；不同 turn 不跨组。
2. 完成的活动组摘要显示“已处理 N 项”及展开图标；仍在执行的活动组显示“处理中…”，可附已知调用数。点击／键盘激活摘要后，按原顺序展开该组**当前已加载的每段调用**，再次点击收起。展开态在同一会话的流式更新、补页和重排后尽量保持；切换会话时可重置。手机和桌面语义一致。
3. 展开的每段调用至少显示可辨别的工具类别、原生名称或命令、当前状态；原生已提供且经 Adapter 验证的参数、输出、文件路径或 diff 作为详情呈现。没有可靠详情时直说“当前历史没有更多详情”，不显示猜测的占位。单 item 展示详情至多 16 KiB；超出时明确标注截断并提示到原 Codex Desktop 查看完整内容，不静默假装完整。
4. 当前 turn 运行中、尚未有待用户处理的请求时，正文末尾最多一条轻量状态：“思考中…”用于尚无可见工具活动的阶段，“处理中…”用于最近活动是工具过程的阶段。已有活动组的运行中摘要可承载“处理中…”，不能重复出现第二条状态。turn 完成、停止、失败、切换会话或 Agent 断开后移除运行中状态，但已完成的活动组仍可按需展开。
5. 命令／文件／权限审批和补充提问仍显示原有完整交互卡片与操作内容；待用户决定时不显示误导性的“处理中…”，折叠活动不隐藏、禁用或替代任何审批按钮。未知交互仍维持不支持的明确提示。
6. 折叠／展开不发起变更请求，不改变会话草稿、滚动到最新的用户意图或阅读位置；与 [0017](0017-preserve-reading-position-on-live-updates.md) 的滚动锚点规则配合。

## 归类、协议与容量边界

- 第一批明确归类的原生工具过程：`mcpToolCall`、`commandExecution`、`fileChange`、`sleep`、`imageView`。仅以版本化 Adapter 识别的原生 `type` 分类；真正未知类型保留可见的兼容性提示，不因名字含 `Tool` 就吞掉。`reasoning` 不展示正文或内部推理内容，只可参与粗粒度“思考中…”状态。畸形 item 仍按现有 `ErrNativeShape` 失败。
- Web 的 `item` 增加可选的、向后兼容的工具活动字段，携带类别、短标签、状态、经验证的有界详情与“已截断”标记；原有 `itemId`、顺序与 `role/text` 保留。旧 Agent 缺少新字段时仍按现有系统消息显示，不把未知数据伪装成已折叠。Relay 只转发，不解析或持久化调用详情。
- 详情最多 16 KiB 是**显示投影**的边界，不改变原 owner 的 64 MiB 本机读取上限、Relay→Web 的 8 MiB 单帧上限、0013 的逐页预算或原生 cursor。默认折叠不表示不读取这些有界详情；无论是否展开，传输仍要遵守原有页面预算。不得把完整 64 MiB 会话一次送到手机。
- 历史页若全是工具活动，`thread.history`／`thread.history.items` 的 cursor、`itemsComplete` 和 `nextItemCursor` 仍须正常前进。工具组跨 item 页边界时，已加载部分可先显示并注明还有更早内容；不得丢失旧正文、重复 item 或把未加载的调用计入已展示数量。
- detail 中可能包含路径、命令参数或工具输出，仅发送给已通过 Web 鉴别的订阅者；不落盘、不写正文日志、不上传额外服务。来自原生的文本只作为普通文本节点渲染，不执行 HTML，也不把工具输出当作指令。

## 错误与验收

- Agent／Relay 断线、分页失败或未知原生 shape 时，不把折叠摘要误写为“全部加载完成”；当前已加载内容和明确错误提示保留。单条详情超限有可见截断提示；审批请求上下文超限仍沿既有门禁，不因工具折叠而放宽。
- 先写失败的 Agent／协议测试：上述已知类型有稳定的活动标记与安全详情，未知类型可见、畸形报错、16 KiB 截断明确；纯工具页 cursor 仍前进，审批卡仍保留。
- 先写失败的 Web 测试：连续调用默认只占一行，展开后顺序和数量正确；正文分隔产生多个组；进行中“思考中…”／“处理中…”不重复，终态／断线清除；键盘、触屏与 Night 对比度可用。
- Red 测试实际失败后再实现，运行 Go／Web 全量测试和构建。用只读真实大会话在浏览器核对大量 MCP 调用的折叠／展开、手动翻页与滚动位置；物理手机由用户复验。任何发送或审批测试仍只在隔离 fixture 上做。
