# 0015：会话中的工具活动折叠为单行状态

- 状态：Draft（2026-10-05，待用户确认；不得开始实现）。
- 来源：用户在手机会话中看到大量重复的“系统 / [mcpToolCall 项目]”，要求过滤这类 tool call 信息，以一行“思考中…”或“处理中…”表示 Agent 当前状态。
- 范围：Ariel Web 的手机与电脑会话正文；原生历史读取、原 owner 状态、安全审批和发送语义不变。与 [0013](0013-paged-history-and-large-owner.md) 的关系：只改变已知工具活动的**展示投影**，不减少原生历史读取额度、不改变 turn／item cursor 或分页完整性标记；0013 中“工具／文件变更 item 不得静默截断”的展示要求，在本规格获批后由下列显式折叠规则取代。

## 用户看到的结果

1. 浏览历史时，`mcpToolCall`、命令执行及文件变更这类工具过程不再各占一张“系统消息”卡片，也不显示 `[mcpToolCall 项目]` 一类技术占位。真实用户消息、Codex 正文、计划文字和已回答补充问题的记录仍按原顺序显示。
2. Codex 正在运行且尚无待用户处理的审批／提问时，当前 turn 在正文末尾最多显示一条轻量状态行：纯推理／等待下一步时为“思考中…”，最近的原生活动属于工具执行时为“处理中…”。状态行不重复列出调用次数、参数、路径或工具输出，也不与现有“正在生成”文案叠加。
3. turn 结束、停止、失败、切换会话或 Agent 断开后，不再显示“思考中…”／“处理中…”这种进行中提示。已有的完成／停止／失败提示和错误消息仍可辨识；不能把历史 turn 的 `inProgress` 字段误当作当前正在运行。
4. 命令、文件、权限审批或补充提问**仍以原有完整交互卡片呈现**，包含操作内容、风险提示和可用决定；等待用户决定时不显示会误导为“Agent 正在处理”的状态行。折叠工具过程不改变审批门禁、拒绝语义或交互回执。

## 归类与数据边界

- 明确归类为“工具过程”的已知原生 item：`mcpToolCall`、`commandExecution`、`fileChange`；`reasoning` 仍不生成正文消息，而作为“思考中…”的活动信号。连续多少条同类过程都只影响**当前**那一条状态行，历史中不保留状态行。
- `userMessage`、`agentMessage`、`plan`、`userInputResponse` 保留既有可见语义；真正未知／无法安全分类的 item 继续显示明确的兼容性占位或错误，不因名称含 `Tool` 就一律吞掉。畸形 item 仍按现有 `ErrNativeShape` 失败，不伪装为正常完成。
- Agent 从原 owner 和分页 API 读取的 native items 仍按 0013 的容量、顺序和 cursor 校验；仅发往 Web 的展示投影省略已知工具过程。状态基于原生类型与当前 owner runtime 推导，不通过解析中文占位文案推断。Relay 不保存过程记录、正文或新增数据库。
- `thread.history` 和 `thread.history.items` 即使一页只含折叠掉的工具 item，也必须让原生 cursor 正常前进，并维持 `itemsComplete`／`nextItemCursor` 的真实语义；不得因展示页为空而丢失更早的正文消息、卡在“加载中”或制造重复 item。
- 一次 turn 中若先工具调用、后 Codex 继续输出文字，状态要随最新原生活动更新；状态只描述粗粒度阶段，不能暗示具体工具已成功、变更已批准或可安全发送。状态行应有可访问文本、清楚的 Night 对比度，但不反复播报每条 tool call。

## 错误与边界

- 正在处理时的历史页加载失败，只保留已显示的内容和现有错误提示；不因为工具过程被隐藏就谎称完整。单个未知 item 或新版本原生类型保持可见的兼容性信号，等待版本化 Adapter 适配。
- 工具项很长或数量很多时，Web 展示数据与 DOM 不应随工具条数线性增加；但本规格不承诺减少本机原 owner 帧本身的字节数，也不提高 Relay→Web 的 8 MiB 单帧上限。
- 手机和电脑使用同一过滤与状态语义；只允许样式随断点变化。状态行不得占用一整张消息卡片或遮挡审批卡、输入框。

## TDD 与验收

1. 先写失败的 Agent 规范化测试：大量连续 `mcpToolCall`、命令、文件变更不会生成系统消息；用户／Codex／计划／补充回答保持顺序；未知类型仍有兼容性提示，畸形数据仍报错；进行中阶段和终态的状态推导正确。
2. 先写失败的分页测试：整页只有工具过程、工具过程与正文跨页交错时，原生 cursor、`itemsComplete` 与更早正文都能继续加载；审批卡片不随工具过程一起消失。
3. 先写失败的 Web 测试：当前 turn 只有一条“思考中…”／“处理中…”状态，后续正文和工具阶段能更新它；终态、断线、切换会话和待审批时不留下虚假的进行中状态；手机与桌面均没有重复工具卡片。
4. Red 测试确实失败后再实现、跑绿并重构；运行 Go／Web 全量测试与构建。用只读的真实会话或隔离 fixture 在浏览器核对长串 MCP 调用压成一行、历史仍可按需翻页、审批仍能看见；任何写操作只在隔离 fixture 上测试，物理手机由用户最终复验。
