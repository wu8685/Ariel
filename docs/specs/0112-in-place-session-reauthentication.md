# 0112：原地恢复登录，保留当前会话

- 状态：Implemented（2026-10-26；用户明确要求原地重试／刷新登录状态并合并发布当前能力；验收见下方记录）。
- 关联：0108、0109、0110、0111。0108 的错误分类与严格 wire 校验保持不变；本规格替换其认证失效后的清空页面行为。

## 输入与输出

- 输入：当前 WebSocket 明确的 `1008 / unauthorized`、同源认证状态响应、用户主动发起的 Passkey／PIN 登录、显式退出。
- 输出：原页面内的续登录提示和恢复后的连接；不导航、不刷新页面、不重新发送任何业务 mutation。

## 行为与不变量

1. 已有会话或新会话草稿时，认证失效保留会话／设备选择、已加载正文与历史、阅读位置、草稿文本／图片／文件引用和模型选择；输入区允许继续写草稿。发送、停止、审批、回答、模型设置等远端操作暂停，直到连接和最新 owner／cache 状态重新确认。
2. 提示放在会话区域内，手机端不遮挡正文或输入区；不再展示登录整页或额外 masthead。首次访问没有会话上下文仍使用原登录页。
3. Passkey 失效时最多自动检查一次同源 `/api/auth/status`；若 Cookie 仍有效，重建连接。检查失败、凭据失效或自动恢复再次被拒绝时，保留现场并等待用户点击“重新登录”。成功后短时间再次被拒绝也不得形成自动登录循环。
   - 自动恢复检查最多每 30 秒一次，单次状态请求 15 秒超时，超时后开放手动登录，不阻塞在无限等待中。
4. Passkey ceremony 只由用户手势发起；取消、错误和网络异常均在原地显示可重试提示。PIN 模式在原地输入新连接码，不自动重复错误 PIN。
5. 登录成功恢复原会话的 watch，并继续增量同步；旧正文不消失，新的 owner 状态确认前不得提前恢复 mutation。未确认的发送不得重放。
6. 显式退出仍清理会话与草稿，并使晚到的认证／状态检查结果失效。组件卸载也不得被晚到结果重新连接；每次用户认证代次隔离。
7. 协议不兼容仍显示独立刷新提示，不触发登录；不放宽 schema、延长 Cookie 寿命、修改认证密钥或把正文上传到新位置。

## 边界与错误处理

- 在后台检查中点击手动登录／退出：旧响应无权覆盖新状态或恢复旧连接。
- HTTP 状态有效但 WS 持续 unauthorized：自动恢复有界，转为用户动作，不反复弹出 Passkey 或循环重连。
- 认证期间 device／thread 请求晚到：既有 generation／subscription 栅栏继续丢弃旧结果。
- 已打开的文件内容和交互回答保留；远端文件读取暂不可用，恢复后按既有受控网关读取。
