# 0018：黑色 Night 主题与左右分列对话气泡

- 状态：Draft（2026-10-05，待用户确认；不得开始实现）。
- 来源：用户希望背景回归黑色，蓝色只用于必要的高亮；用户与 Codex 的正文分别以右侧蓝色气泡和左侧中性气泡呈现，不再显示可见的“我／Codex”名字。
- 范围：Ariel Web 的手机与电脑共用主题及会话正文；获批后覆盖 [0007](0007-night-appearance.md) 的具体色板，不改变原 owner、消息顺序、历史分页、发送、审批、权限和 Relay 协议。与 [0015](0015-compact-tool-activity-in-conversation.md) 的工具组、[0017](0017-preserve-reading-position-on-live-updates.md) 的滚动规则独立实施，但样式应兼容两者。

## 视觉与行为

1. Night 的页面主背景改为近黑色；侧栏、输入区、Codex 气泡用层次清楚的深灰中性色，不再把大面积面板染成蓝黑。主文字保持高对比的近白色，次级文字与边框用中性灰。Logo 继续为灰色。
2. 蓝色仅用于需要强调的交互和状态：用户消息气泡、可发送时的发送按钮、当前选中会话、键盘焦点和少量关键操作。普通标题、分区眉题、空状态图形、运行中状态及已完成状态改用中性文字；在线成功与风险警示仍用各自语义色，不强改为蓝色。
3. 每条 `user` 正文靠右，以蓝底白字的圆角气泡显示；每条 `assistant` 正文靠左，以深灰底近白字的圆角气泡显示。手机和桌面使用同一左右语义，气泡宽度受正文区域约束，不因长文本、路径、换行或代码片段使页面横向溢出。连续同角色消息仍逐条保留原顺序和 item 身份，不合并、丢弃或改变内容。
4. 正文气泡不显示头像、可见的“我／Codex”角色名。保留可供辅助技术识别的角色标签（例如文章的 `aria-label` 或 visually-hidden 文本）；角色不能只靠颜色区分，左右位置也必须一致。空的流式 assistant item 保留轻量思考提示，不画没有内容的普通气泡。
5. `system`、未知类型兼容性提示、turn 状态、历史分页入口和交互卡片不冒充用户或 Codex 气泡：使用中性、紧凑且可辨识的呈现。审批、权限风险、断线与错误提示保持明显，不能为了极简视觉隐藏关键信息。0015 获批后，工具活动摘要及展开详情亦使用中性层级。
6. 气泡背景、文字、链接、按钮的默认／hover／focus／disabled 状态在手机与桌面均可读；蓝底白字、深灰底近白字的正文至少达到 WCAG AA 普通文字对比度 4.5:1。页面缩放、窄屏键盘与侧栏打开时，发送按钮和气泡不越界。

## 边界与验收

- 本规格不引入主题切换开关、头像、额外动效或新图标；继续只提供 Night 模式。对旧历史、只读降级及正在同步的会话也应用同一布局。
- 先写失败的主题／组件测试：近黑主背景与中性面板 token、蓝色使用范围、两类气泡的位置和对比度、可访问角色标签、system／审批独立呈现、长内容不横向溢出。Red 确认后再实现，运行 Web 全量测试与构建。
- 在隔离 fixture 的浏览器中分别以手机和电脑宽度目测：黑色 Night 层级、左右气泡、长消息、空／运行中／错误／审批状态，以及输入框聚焦时的布局。物理手机由用户最后复验；不得用真实会话做写入测试。
