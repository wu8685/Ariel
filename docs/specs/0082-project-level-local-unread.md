# 0082：项目级本地 unread 标记

- 状态：Implemented（2026-10-14；Web 全量测试、真实移动 Chromium、production build 与公网 Docker 已验证）。
- 来源：Web 已按 0077 在会话行展示本地 unread 蓝点；用户希望项目折叠时也能看出项目内存在未读会话。
- 关联：[0077 Web 本地会话未读标记](0077-web-local-thread-unread.md)。
- 范围：Web 侧项目标题的 unread 聚合与展示；不增加 Relay／Desktop Agent／Codex API，不新增请求或持久化字段。

## 用户行为

1. 当前列表中，同一项目内只要有一个会话处于 unread，项目标题右侧显示与会话一致的蓝点。
2. 项目展开或收起只改变列表可见性，不清除项目或会话 unread。
3. 用户按 0077 的规则成功查看一个 unread 会话后，该会话蓝点消失；项目内仍有其他 unread 会话时，项目蓝点保留。
4. 项目内最后一个 unread 会话被成功查看后，项目蓝点立即消失。
5. 首次观察、无效或倒退的 `updatedAt`、metadata 更新等既有规则保持不变。

## 聚合语义

1. 项目身份继续使用 `normalizeProjectPath(cwd)`；相同规范化路径下的会话聚合为同一项目。
2. 聚合来源是当前 Web 已有的批量会话列表与 `unreadThreadIDs`，不得为每个项目或会话新增网络请求。
3. 置顶会话仍属于其 `cwd` 对应项目。若该项目同时存在普通会话并显示项目标题，置顶会话 unread 也会点亮该项目标题；会话本身继续只在置顶区展示，不复制到项目列表。
4. 仅包含置顶会话、因而当前侧栏没有项目标题的项目，不额外创建空项目分组。
5. 搜索结果只聚合本次搜索返回的会话；不得用搜索前的隐藏列表制造不可解释的项目 unread。
6. 未知路径会话沿用“未知项目”分组并正常聚合。

## UI 与可访问性

1. 项目蓝点使用与会话 unread 相同的尺寸、颜色与光晕，放在项目名称同行，不挤压路径或会话数量。
2. 标记提供 `role="status"` 和可访问名称“项目有新结果”。
3. 项目标题在折叠和展开状态下都显示标记；移动端窄宽度下名称保持省略，蓝点和数量不得被挤出可视区域。

## 状态与错误边界

- unread store 不可用或解析失败时沿用 0077 的 fail-open：不显示会话或项目蓝点，不影响列表。
- 会话移动到另一个 `cwd` 后，按当前列表中的最新项目归属重新聚合，不保存独立项目水位。
- 列表刷新失败时保留现有会话和项目标记；成功刷新后随当前列表重新计算。
