# Codex 远程交互系统需求与决策

## 目标与文档性质

昊天希望通过自己的手机与电脑 Web 页面，继续使用电脑端 Codex 中已有的聊天。手机发出指令，电脑端 Codex 执行，手机实时看到回复、任务状态，并能停止任务、审批操作及回答补充问题。

这是研发前的需求基线，不是完成报告。本文区分三种信息：已确认决定、建议实现方式、尚未验证能力。后续 Agent 不应把建议当作用户已确认，也不应把本机实验当成跨版本保证。

## 已确认决定

| 编号 | 决定 | 对实现的约束 |
| --- | --- | --- |
| D01 | 三个组件在同一项目内开发 | Web、Relay Server、Desktop Agent 采用 Monorepo |
| D02 | Relay 是通信枢纽 | Web 和 Desktop Agent 均主动连 Relay；Relay 不主动连接电脑 |
| D03 | 先局域网，后公网 | 不以完整账号系统、公网运维和复杂加密方案阻塞首版 |
| D04 | Codex 会话记录为 SSOT | Agent 和 Relay 不复制保存一套会话库 |
| D05 | Agent 和 Relay 不做业务持久化 | 可有配置文件和有界内存；无离线消息队列、数据库及持久化事件日志 |
| D06 | 共用响应式 Web 页面 | 不开发原生 iOS、Android 或另一套桌面前端 |
| D07 | 首版只支持已有会话 | 不区分“本系统创建”与“原来已有”；但不做新建入口 |
| D08 | 运行中输入留草稿 | 不做自动排队或 turn steering；可等待或先停止，之后手动发送 |
| D09 | 依赖 Desktop 已运行 | 不自动启动、重启或更改 Desktop 启动参数 |
| D10 | 首版手机可审批和补充回答 | 展示 Codex 的真实待处理请求，响应回同一个执行 owner |
| D11 | 另一台电脑也是 macOS | 首版不承诺 Windows、Linux Desktop 接入 |
| D12 | 项目命名稍后决定 | 归档目录名不是产品名；代码目录与仓库也保留 TODO |
| D13 | spec 先存当前知识库 | 支持跨电脑接续开发；本轮不创建正式代码项目 |

单用户、单台受控电脑、多会话是首版规模边界。同一用户可同时打开手机和电脑 Web 页面；它们不是相互独立的执行引擎。

## 手机怎样选择旧会话

建议提供一个最近会话列表，而不是要求输入 threadId。建议首屏字段如下：

| 字段 | 用户看见什么 |
| --- | --- |
| 标题 | Codex 已有标题；缺失时用内容预览，再缺失显示“未命名会话” |
| 项目 | cwd 的简短显示名；展开时可看完整目录，用于区分同名项目 |
| 更新时间 | 最近更新的时间，按时间从新到旧排列 |
| 状态 | 待检查、可继续、执行中、待你处理、需在 Desktop 打开、暂不支持 |

列表的具体呈现属于提案：首版默认非归档、本机可访问的 Codex 会话；支持分页、刷新、按标题或项目过滤。不做跨设备搜索或聊天内容全文检索。若后端只能过滤已加载页面，UI 必须写“筛选已加载会话”，不能声称搜索了全部历史。

完整选择流程：

1. Web 经 Relay 请求会话列表，Desktop Agent 从本机 Codex 获取并规范化后返回。
2. 用户点选一条记录；内部带上 `deviceId` 和 Codex 原始 `threadId`。
3. Agent 读取历史，发现 Desktop owner，订阅实时快照；历史可读与可控制分开判断。
4. 可控制时开放发送、停止及处理请求。无法找到 owner 时可以只读展示历史，但清楚提示“请先在电脑端打开此会话”。
5. 若后续探针证明可安全自动加载，步骤 4 可由 Adapter 自动完成；否则保留手动打开的可见降级，不伪装成功。

归档会话、云端 ChatGPT 聊天、其他远程主机的会话首版不纳入可控范围。不能从目录可见性推导可控制性。

## 核心用户场景

| 场景 | 预期结果 |
| --- | --- |
| 查看历史 | 看见已有用户文字、Codex 回复、turn 状态；工具活动有摘要，不伪装为普通聊天 |
| 续聊 | 输入普通文本；Codex 接受后显示已发送，随后显示渐进回复 |
| 电脑端主动发送 | 已订阅的 Web 也收到更新，不只显示从手机发起的消息 |
| 停止任务 | 只停止当前指定 turn；请求中、已停止、已经结束分开显示 |
| 同一会话运行中输入 | 可编辑草稿，但不能自动变成下一条任务；待结束后手动发送 |
| 工具审批 | 展示真实命令、目录或文件变更等可用上下文，用户明确选择允许或拒绝 |
| 回答补充问题 | 按 Codex 原问题、选项及允许的自由输入收集回答，不代选、不自动提交 |
| 两端同时处理请求 | 先在 Codex owner 处成功处理的一次生效，另一端显示已处理 |
| 断线重连 | 重新订阅并取得当前快照，不重复执行断线前可能已提交的消息 |
| 电脑离线 | 显示离线，保留当前 Web 草稿，不接受离线排队 |

## 审批不是另起一套安全系统

手机是现有 Codex 交互的另一入口，执行权限仍由本机 Codex 控制。首版必须实现常用命令执行审批、文件变更审批、权限请求以及结构化补充问题；实际请求类型与响应结构需在目标版本验证。

建议只提供 Codex 允许且 Adapter 已验证的最小决定集合，例如单次允许、拒绝。不要自行加入“始终允许”、自动批准或扩大 sandbox 权限。若请求缺少足够展示信息，禁止提供允许按钮。

不认识的 MCP elicitation 或特殊交互需显示明确的不支持原因和回电脑处理入口，不能丢弃，更不能自动批准。此降级不是已承诺常用审批和补充回答能力的替代品。

## 明确不做

- 原生 App、后台 Push 通知、语音、图片和文件上传。
- 新建、删除、归档、重命名、分叉会话，远程终端和文件浏览器。
- 手机上修改模型、权限配置或电脑启动参数；默认继承原会话设置。
- 云端会话同步、第二套会话存储、任务迁移和多电脑执行调度。
- 离线发送、跨重启 exactly-once、逐事件无损回放。
- 在任意 Codex Desktop 版本上无验证即可工作的承诺。

文件 diff 的审批预览属于审批必需内容，不等同于通用文件管理。不同会话可以切换查看；切换页面不停止后台正在执行的任务。

## 仍可继续讨论的提案

- Go 实现 Relay 和 Agent，TypeScript 实现 Web；前端框架未定。
- 列表默认不展示归档会话；首版过滤范围与分页提示按上文实现。
- 未加载旧会话若无法自动接入，首版允许提示用户在 Desktop 打开。
- 浏览器草稿先只放页面内存；刷新后可能丢失。是否加本机 localStorage 可后续单独决定。
- 未知请求类型的降级，以及是否把通用 MCP elicitation 也纳入第一批适配。

这些提案不应阻塞读取规范、编写 Mock、测试协议等准备工作。会改变产品范围的调整，需要回到用户确认。
