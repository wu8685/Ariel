# Codex 远程交互系统开发规格

这是一份交给另一台 macOS 电脑继续开发的 spec 包。目标是在手机和电脑的响应式 Web 页面中，查看并操作电脑端已有的 Codex 会话。三个自研组件是 Web、Relay Server 和 Desktop Agent，放在同一个代码项目内。

文档版本：v0.1，2026-10-03。产品决定已记录；技术协议是实现提案，仍可继续讨论。这里只整理规格和实测依据，尚未开发三端服务，也未完成新一轮兼容性验证。

`codex-remote-control` 仅为知识库归档目录名，不是已选定的项目名。按用户要求，当前 spec 以本目录为准；代码项目建立后再明确文档迁移位置，避免两套规格长期独立修改。

## 已确认的基线

- 手机和电脑共用响应式 Web 页面；首版仅处理已有会话，不新建会话。
- Desktop Agent 和 Web 都主动连接 Relay，Relay 是唯一通信枢纽。
- 会话持久化以电脑端 Codex 为 SSOT；Relay 与 Desktop Agent 不建业务数据库。
- 同一会话运行中，新文字留在草稿；等待结束或主动停止后再发送，不自动排队。
- 依赖 Codex Desktop 已启动，不自动拉起或重启 Desktop。
- 手机端需要审批和回答 Codex 的补充问题，纳入首版，不默认退回电脑处理。
- 首版单用户、单台受控电脑、多个会话，局域网运行；公网加固后置。
- 开发和 Desktop Agent 运行目标都是 macOS；项目名、代码仓库和路径留作 TODO。

## 不可误读的接入结论

已验证的是：当前 macOS 版本可经 Desktop 本地 IPC 对已加载测试会话发送、接收更新和停止任务。单独启动 App Server 可读历史，但没有共享 Desktop 当前执行态。

尚未验证的是：自动加载未打开的旧会话、手机审批和补充回答的完整交互。它们需要小型探针，不必等三端系统开发完成；完整手机体验则需要三端联调。

## 证据附件

[证据目录](evidence/README.md) 以 Markdown 保存本轮早先实测报告和三个探针源码的脱敏版本。真实会话 ID 和用户目录已替换为占位符，仅供查证和改造成新探针，不能直接照搬运行。

同步本目录只是同步设计，不会同步 Codex 登录凭据、会话数据库、代码仓库或电脑运行态。另一台电脑默认控制它自己的本地 Codex 会话。
