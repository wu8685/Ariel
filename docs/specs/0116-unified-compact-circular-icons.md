# 0116：全局统一紧凑圆形操作图标

- 状态：Implemented（2026-10-27 用户授权 14px／28px／44px 方案及联合发布；全量浏览器／几何断言已验，物理 Safari 待复验）。
- 日期：2026-10-27。
- 范围：Ariel Web 各页面、抽屉、弹层中的圆形／圆形 ghost 操作按钮；统一视觉 token 与点击区域。
- 来源：用户希望所有圆形 icon 比现状更小，与邻近文字协调，并保持全局一致。
- 关联：0012 紧凑布局、0111 紧凑 header、0110 模型设置与 0022 Night 主题；本规格批准后替代其中互不一致的圆形按钮视觉尺寸，不改变既有能力。

## 1. 现状

目前可见圆形／按钮尺寸混用 26／28／36／40／44px，内部 SVG 多为 17／18／19／20px，部分关闭／返回控件仍使用 22／24px 字体字符；手机断点和 composer 的条件选择器还会覆盖基础尺寸。这使同一界面的圆形控件比 12–14px 文字更抢眼，也使全局大小不一致。

## 2. 统一尺寸

| 元素 | 全局值 | 约束 |
| --- | --- | --- |
| 主图标绘制框 | 14×14px | 与正文 14px／操作文案 12px 协调，不随手机／桌面断点放大 |
| 可见圆形外框／底色 | 28×28px | 包含边框，圆角 50%，透明 ghost 的 hover 底色也使用同一圆形 |
| 实际点击区域 | 44×44px | 居中包围可见圆形，透明部分同样可点，目标之间不得重叠 |

- 用同一组 token（建议 `--circle-icon-size`、`--circle-visual-size`、`--circle-target-size`）和共用样式／组件表达，不在各按钮重新硬编码。
- 统一绘制框与视觉重心，不以增大某一个 SVG 的 CSS 尺寸补偿空白。必要时校正内部留白／viewBox；停止方块、返回箭头与 loading 不能缩成难以辨识的点。
- 44px 点击区是可点击元素自己的真实布局盒，不通过遮盖相邻控件的扩展层伪造；背景／边框绘制于居中的 28px 视觉层。
- 不给所有图标增加圆形边框：现有透明操作仍透明，只统一其图形大小与 hover 的视觉占位。

## 3. 覆盖清单

1. 会话 header：打开菜单、浏览工作区文件。
2. Composer：附件加号、权限信息、取消编辑、停止、发送及发送 loading。
3. 侧栏：新建、扫码／Passkey、刷新、断开／退出、关闭、搜索清空。
4. 新建／重命名／扫码／模型设置弹层的纯图标关闭入口。
5. 工作区文件浏览器的返回／刷新、文件阅读页的纯图标关闭入口。
6. 会话图片预览关闭、待发送截图移除、回到最新等浮动圆形操作。
7. 模型入口内的推理强度／速度主图形也使用 14px 绘制框，避免仍比旁边按钮图标大；模型名称、12px chevron 和小型状态指示器保留各自语义层级。

不属于本次统一圆形尺寸的元素：品牌 Logo、二维码／登录示意图、在线／未读状态点、计数徽标、radio、目录展开箭头，以及含文字的 pill 按钮（返回、加载历史、引用到会话等）。队列拖拽手柄不是圆形按钮，不改变其尺寸或手势；不把矩形菜单项强改成圆形。

## 4. 行为与不变量

- 图标颜色、可用性、业务处理、请求次数、键盘入口、ARIA 名称、tooltip 和焦点恢复均不变；停止保留此前已确认的蓝色方向，权限 warning 仍为 warning，不因共享组件改色。
- 内联 SVG 使用 `currentColor`；本次覆盖的字体字符关闭／返回／刷新图标换成同体系 SVG，保持原有无障碍名称，不引入第三方依赖。
- loading、普通发送与停止在状态变化时共享同一视觉／点击尺寸，不推挤模型选择或引起输入区跳动；reduced-motion 仍有效。
- 保留会话 header 52px、现有正文与输入字号、展开／折叠、输入焦点及队列排序语义；不借本次改动继续压缩触控布局。
- 菜单按钮状态点锚定可见圆形而非透明点击区，不能悬空或变成单独可点目标。
- 图片角上的移除按钮、右上关闭和侧栏搜索清空同样提供真实 44px 点击区，必须检查图片裁剪、搜索文字可用宽度和相邻按钮命中区域；不能遮挡正文、其他图片或点击打开图片的有效区域。
- 透明视觉层不得拦截指针或与现有 `::after` tooltip 冲突；keyboard focus 清楚、disabled 不能仍响应透明点击区，弹层不能因新增容器被裁切。

## 5. 输入、输出与错误边界

- 输入仍为现有图标、状态、颜色语义及事件回调；输出为统一尺寸的操作控件，不改变设备／thread／owner 身份、协议、权限或数据。
- 组件边界允许明确的 visual tone 和 loading 状态，不提供各页面自行传入不同尺寸的公开逃生参数。
- 长标题／模型名、320px 小屏和 viewport resize 时，优先截断可省略文字，不缩放圆形图标，不叠放或缩小真实点击目标。
- UI 尺寸规范自身不扩展协议；用户于 2026-10-27 已另外批准 0114／0115 一起开发和联合发布。

## 6. TDD 与 UI 验收

1. 先写并实际运行失败测试：覆盖清单中的控件均引用统一 token／样式，不存在手机／桌面、能力条件或 Portal 中恢复旧尺寸的规则。
2. 组件测试覆盖 ARIA、disabled、防重复回调、点击 28px 可见圆形之外但 44px 点击区之内、键盘激活、SVG 与 loading 替换。
3. Chromium 在 320／390／1280px 量测：可见圆形均 28px、主图标均 14px、实际目标均 44px；验证相邻目标不重叠，页面无横向溢出，header／composer 不增高或跳动。
4. 固定截图覆盖 header＋composer、打开侧栏、模型设置、目录／文件阅读、图片预览／待发送图片及回到最新；更新既有基线前逐项检查几何与交互，不能批量接受未知变化。
5. 320px 下同时存在权限、长模型名、队列编辑取消、停止和发送时，保留各操作可用且无交叠；触摸透明边缘也只能触发其对应控件一次。
6. 回归 tooltip／权限弹层、文件选区引用、截图移除、历史折叠、输入与 streaming、所有现有 Web 单测／build／浏览器用例。
7. 浏览器全部使用隔离 WebSocket fixture，不对真实 Codex 会话执行测试写入。Chromium 手机模拟不代表物理 iPhone／Safari，最终触感与真机显示留用户复验。

确认以上 14px／28px／44px 尺寸后进入实现；完成后按项目约定验证、push 并关联 PR，未获发布授权前不部署。
