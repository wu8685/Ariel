# 0115：停止后编辑并替换最后一条用户消息

- 状态：Implemented（2026-10-27；精确版本原生隔离写门禁、Go／race／vet、Web／Chromium 已验；附件与其他 native 版本保持 unsupported）。
- 日期：2026-10-27。
- 范围：Web 消息编辑入口／composer 状态、显式编辑协议、Desktop owner 版本化 Adapter 与历史缓存失效。
- 关联：0100 Relay hot cache、0102 低延迟发送、0089 文件上下文、0092 独立会话草稿、0110 模型设置及 0112 原地认证恢复。
- 兼容性依据：[本机静态核对与隔离运行态门禁](../compatibility/2026-10-27-edit-last-user-turn-static.md)；仅启用精确已验证版本组合，附件编辑仍为 unsupported。

## 1. 用户体验与首版范围

1. 用户发送一条消息，随后点击停止（用户所说“取消”按停止当前执行理解）；收到权威 `interrupted` 状态且会话 idle 后，在该用户消息下显示小铅笔按钮，名称为“编辑并重新发送”。停止请求的 receipt 本身不能提前开放编辑。
2. 首版只允许编辑最近一个用户 turn 的原始消息，不开放任意历史 turn、失败或已完成 turn 的重写；存在后续用户输入、待处理交互、待执行队列或不确定状态时禁止提交并说明原因。
3. 点击铅笔把原始文本填入底部输入框并聚焦，显示“正在编辑上一条消息”和取消编辑入口；发送按钮可访问名称改为“重新发送”。**进入／退出编辑均不修改 Codex 历史。**
4. 发送时走原生编辑链路；成功后以最新文本及新执行结果替换旧的已停止 turn，而不是追加一条修正消息，也不是只在 Web 隐藏旧内容。
5. 被替换的是这个 turn 的对话历史，包含其已产生的部分回复／工具记录；不会自动撤销已经发生的文件修改或其他副作用。编辑区给出简短说明，不提供撤销文件／命令的假承诺。
6. 铅笔使用现有内联 SVG 和紧凑视觉，触控区域至少 44px；支持键盘、tooltip 和无障碍名称，不挤占气泡正文、不导致移动端横向溢出。

## 2. 输入恢复与草稿

- 输入恢复使用真实用户文本而不是渲染后的 Markdown、工具摘要或拼接出的系统上下文。
- 当前 composer 已有未发送文本、图片、文件引用或队列编辑时，不静默覆盖，先提示处理当前草稿；普通发送和队列编辑与历史编辑互斥。
- 文本编辑仅替换用户文字；原消息其他 input 的保留必须经 compatibility gate 验证。图片／文件引用／多段 input 无法可靠恢复并保留时，对这类消息明确禁用编辑，不能丢附件后假装完整重发。
- 暂不在历史编辑模式修改附件或模型／权限设置；使用已验证的原生继承语义，不能因编辑提升权限。普通 composer 的模型选择仍按 0110 工作。
- 编辑草稿按 deviceId＋threadId 隔离；切换会话、认证恢复或 WebSocket 重连不把内容带到别的会话，也不自动提交。取消编辑保留原会话历史；新出现后续 turn 时使编辑目标失效，但保留已写文本供用户自行复制。

## 3. 显式协议与状态归属

- 新增 Web 公共能力标记与专用编辑请求（建议 `turnEditLastUserMessage`／`turn.edit`）；仅由通过运行态门禁的 Desktop Agent 上报，缺失能力时不显示可操作入口。
- 请求绑定 deviceId、threadId、expectedTurnId、expectedItemId、原始内容摘要／revision、clientOperationId 和新 text；Relay／Agent 校验长度、额外字段、身份及 epoch。不得允许客户端指定删除范围或任意历史列表。
- Desktop Agent 在当前 hot controller 上现场核对目标确为最新的 interrupted 用户 turn、会话 idle、owner／epoch 未变化、无队列／交互及输入完整性；不能信任 Web／Relay 缓存的可编辑判断。
- 每个 thread 的编辑与发送／停止／队列写操作协调，编辑期间防止重复提交。Ariel 的本地锁不能代替 Desktop 原生并发保护；外部客户端竞争须由原生 gate 和后置验证覆盖。
- 优先经当前 Desktop owner 的原生“编辑最后一条用户消息”操作执行，由版本化 Adapter 封装私有方法名。禁止独立 App Server 修改 live owner 历史，禁止直接改日志／数据库，禁止前端拼接假历史。
- 不传入额外权限／模式覆盖或用户不可见的上下文标记来辅助对账；公共回执不得泄露原始 IPC 内容。

## 4. 成功、失败与不确定结果

- `accepted` 必须有权威证据：原目标已从当前历史移除，新 turn／用户 input 与本次编辑可靠关联，前序历史未改；不能只凭 transport 的 `ok: true` 或新消息文本相同判定成功。
- 执行前拒绝为 `rejected`，原历史不变，编辑稿保留；目标过期、busy、unsupported、原始输入不完整均为明确错误。
- native 编辑内部可能先回退再发送，**不承诺原子事务**。已修改历史后发生错误／掉线，或无法确定新 turn 归属时返回 `unknown` 与经核实的阶段；保留编辑稿、禁止自动重发或再回退一次。
- 明确观测到“旧 turn 已回退、新 turn 未发送”时，如实展示该状态；不能继续把旧内容当现行历史，也不能自动恢复并再次执行原请求。
- unknown 后仅做一次有界只读对账；确认当前状态后用户才能显式选择下一步。重连、重新认证、刷新页面均不重放编辑 mutation。
- 同一 clientOperationId 在 Agent 当前进程内有界去重，仅保存必要身份／阶段／回执，不长期保存正文；跨重启结果无法核实时按 unknown，不承诺原生 exactly-once。

## 5. Streaming 与缓存

- 展示链路仍走既有长期 follower → Relay 两 turn cache → Web watcher，不增加高频轮询或全量历史同步。
- 历史替换不是 append-only：Agent 必须使旧游标／旧 turn 的派生数据失效，并向 Relay 发布带新 revision 的权威替换快照；Relay／Web 不得用按 turn ID 合并的逻辑把被回退的 turn 重新拼回来。
- Web 丢弃受影响的分页锚点、工具详情、文件变更及图片索引；未改动的较早内容可保留，无法证明有效的分页缓存重新按有界历史页建立。
- 两个 Web watcher 与 Desktop 在不手动刷新时都应看到替换结果；旧 stream／旧 revision／晚到 delta 不得复活旧 turn 或清空新草稿。
- 若原生通知未暴露足够变化，允许提交后一次定向有界 refresh，不新增定时 Agent 轮询；前序稳定正文和输入框保持可交互。

## 6. Compatibility gate 与 TDD 验收

1. 先完成隔离 fixture 的 native 写门禁：发送 → 精确停止 → 编辑重发 → Desktop 可见／持久历史／follower 三方核对；不对真实工作会话试写。
2. 先写并运行失败 UT：编辑资格、原始输入恢复、不同草稿隔离、取消无 mutation、原始内容／turn／epoch fencing、只发一次请求、无权限升级、未知结果无重试。
3. 测试 Desktop 与另一 Web 在编辑期间续聊、目标变化和同文竞争；无法可靠识别结果时 fail closed／unknown，绝不修改更新的 turn。
4. 故障用例覆盖调用前失败、回退后 start 失败、回执丢失、刷新／断线／Agent 重启；分别断言历史、草稿、请求次数及阶段提示。
5. Agent／Relay／Web 跨层测试先复现旧 turn 被增量合并复活的问题，再验证替换快照、旧帧隔离、历史游标失效与两个 watcher 一致。
6. Chromium 在 320／390／1280px 验证停止后铅笔、单击回填、取消、重新发送、长文本、草稿保护、滚动／焦点和禁用状态；对隔离 WebSocket fixture 断言真正替换而非新增消息。
7. 若开放含图片／文件引用的消息，分别验证附件原样保留、lazy 加载不退化；未通过项保持 unsupported，不把纯文本测试结果外推。
8. 执行 Web 全量／build／浏览器回归及相关 Go 全量、race、vet；物理 iPhone／Safari 留待用户复验。

## 7. 非目标与交付边界

- 不编辑任意历史、不永久删除会话、不 fork 成新会话、不回滚工作区文件，不提供离线编辑提交队列。
- 用户于 2026-10-27 已批准与 0114／0116 一起开发验收和发布，原生门禁未通过不得声称 supported。
- 本规格批准前不开始实现；运行态门禁未通过前能力为 unverified，不 push 发布或部署未验证能力。
