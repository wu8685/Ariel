# 0127：宽屏文件／主会话分屏与常驻会话菜单

- 状态：Implemented；用户于 2026-10-28 批准直接开发、push 与部署；368 项 Web 单测／152 项完整 Chromium／生产构建／Go 全量及 vet 通过，物理 Safari 待复验。
- 日期：2026-10-28。
- 用户场景：电脑浏览器有足够宽度时，同时阅读文件和操作主会话，避免反复最小化文件、展开会话菜单。
- 归属：Ariel Web。无 Relay／Desktop Agent／Codex IPC／Chilling 变更。
- 关联：0122 文件工作区、0123 刷新恢复、0118 阅读模式及其视觉维护、0111 紧凑 header、0112 原地恢复认证。
- 范围修订：0122 明确要求所有屏宽均“文件／会话二选一”。本规格获批后，仅取代其宽屏展示、焦点隔离及引用后收起行为；窄屏继续遵循原约定。不是第二阶段侧边新对话，不创建、fork 或复制会话。

## 1. 展示规则

以浏览器 CSS viewport 宽度判断，不根据 User-Agent 或物理屏幕分辨率判断。

| viewport／文件状态 | 左侧会话菜单 | 主内容区 |
| --- | --- | --- |
| ≥1200px，文件展开 | 默认常驻，可手动收起 | 文件在中间，当前主会话在右侧，两者同时可读、可交互 |
| ≥1200px，无文件或文件已最小化 | 默认常驻，可手动收起 | 主会话占满菜单外的剩余空间；已有文件保留恢复入口，不留空文件列 |
| <1200px，文件展开 | 沿用抽屉菜单 | 文件占满内容区；主会话保留挂载但隐藏且 inert |
| <1200px，无文件或文件已最小化 | 沿用抽屉菜单 | 沿用现有会话展示 |

宽屏布局顺序为：`会话列表（280px）｜文件面板（内容区约56%）｜主会话（约44%）`。菜单收起时，其宽度交还内容区；文件与会话仍左右并排。不做上下分屏。

- 分屏的可用内容区在菜单展开时仍至少约 920px；文件最小 480px、主会话最小 400px，边框计入布局。1200px 边界必须实际测量，不能因 min-width 叠加导致页面横向溢出。
- 文件面板指已打开文件的 Tab／原文／Markdown 阅读／Diff，不将目录选择器改为第三种常驻业务面板。目录入口、文件菜单及按需引用栏沿用现状。
- 延用现有色彩、紧凑图标与 44px 操作区域。列间使用一条弱分隔线，不增加装饰性大边框；文件阅读字体、行距、720px 最大阅读列保持，窄列内按实际可用宽度自然换行。
- 第一版不增加拖拽分隔条、自由调整列宽或布局设置菜单；不因本功能新增持久化 schema。

## 2. 菜单与模式状态

1. 宽屏初次进入时菜单展开并占据独立布局列，无遮罩，不盖住文件或会话。选择／新建主会话后不自动收起。
2. 保留手动收起／展开入口，aria-expanded 反映实际可见性；宽屏主动收起后，不因 streaming、切换会话、打开文件或登录恢复重新展开。本次页面生命周期内记住该选择，刷新后默认展开。
3. 宽屏的菜单偏好与窄屏抽屉状态独立。跨断点进入窄屏时抽屉默认关闭，不把原常驻菜单变成覆盖正文的遮罩；返回宽屏恢复本页的宽屏偏好。窄屏选中会话后仍自动收起抽屉。
4. 不能只修改 CSS：当前 showList、DevicePicker.visible、后台未读刷新条件、Escape 处理，以及主会话的 inert／aria-hidden 都必须依据实际布局模式协调。隐藏菜单不得有可 Tab 进入的后台控件。
5. 宽屏常驻菜单的 Escape 不自动收起它；已打开的菜单／弹层优先处理 Escape。窄屏抽屉维持既有 Escape 关闭行为。

## 3. 文件与主会话交互

1. 分屏是同一个文件工作区和同一个主会话同时显示，不另建窗口、DOM 会话副本或新的 thread。原有主会话 DOM、草稿、队列、历史及连接保持。
2. 宽屏主会话不得因文件展开而 visibility:hidden、inert 或 aria-hidden；可以继续输入、发送、查看更新和处理既有权限允许的交互。窄屏文件独占内容区时继续隐藏并隔离主会话焦点。
3. 文件、会话及左侧列表分别纵向滚动，不互相带动，不把整页变成滚动容器。长代码／公式／表格仅在自身区域横向滚动，不撑宽会话列或遮住 composer。
4. 文件最小化后，主会话扩展到菜单外的完整内容区；重新展开恢复激活 Tab、模式、捕获选区和有效阅读位置。关闭最后一个 Tab 与最小化具有相同的主会话空间回收效果。
5. 用户点击“引用到会话”：继续保留已有草稿并增加引用，焦点进入主会话输入框；宽屏保持文件面板展开，便于继续对照，窄屏沿用引用成功后收起文件的行为。只允许来源 thread 与当前主会话一致的引用；切换会话不能把旧文件引用改绑到新 thread。
6. 文件打开、最小化、关闭后的焦点恢复沿用现有规则。Escape 仅在文件区域拥有焦点且无更高层菜单时收起文件；在主会话输入框、列表或其他区域按 Escape 不收起文件。
7. viewport 跨断点、浏览器缩放或窗口大小改变时，只切换展示模式，不重建文件／主会话，不清除草稿、Tab 或选区，不发起新的读取／watch。分屏转独占时若焦点落在将被隐藏的会话中，迁入文件工具栏；不自动提交或丢弃输入，IME 输入完成前不粗暴转移焦点。
8. 模式变化不主动回到顶部／底部，优先保持原可见内容锚点；宽度导致自然重排时限制位置在有效范围，不承诺跨宽度像素级一致。主会话的跟随最新／阅读历史意图、文件独立滚动状态不互相覆盖。

## 4. 状态、资源与失败边界

- 输入：现有文件工作区模型、展开状态、当前主会话、viewport 模式、宽屏菜单偏好及窄屏抽屉状态。新增状态仅表达布局，不保存正文或操作。
- 输出：单一工作区中的可见列、可访问性属性与焦点位置；网络请求与现有业务动作保持一致。
- 0123 的刷新恢复继续适用：文件展开状态在当前宽度决定分屏或独占，最小化仍不预读正文；只恢复一个激活文件。认证／设备／epoch／能力核验顺序不变，不显示未获授权的文件路径。
- Tab 数量不设固定上限，仍只挂载一个激活文件正文，复用现有有界正文／Diff LRU 和 lazy 图片；不为每列／每 Tab 创建 WebSocket、watch、follower、文件轮询或后台预读。
- 菜单常驻只复用现有实际可见菜单的未读刷新策略（当前 15 秒合并刷新）；不增加频率、不新增逐会话读取或 timer，隐藏页面仍暂停对应工作。
- 文件失败只影响该 Tab；会话断线／认证恢复仍原地处理，不因布局跳转登录、重放发送或丢弃文件现场。文件能力关闭时没有空面板，主会话保持可用。
- 本功能不修改任何 Agent 能力探测、消息协议、owner／引用授权边界或 Chilling 依赖方向。
