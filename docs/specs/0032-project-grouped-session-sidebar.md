# 0032：左侧会话按项目分组

- 状态：Implemented（自动测试与 production build 已验；物理手机视觉待用户复验）。
- 背景：Ariel 当前把 Codex 原生会话平铺在左侧列表。每个会话已经带有权威 `cwd`，但同一项目的会话没有形成清晰的视觉分组，后续也无法自然承载“在某个项目中新建会话”的入口。
- 依赖：沿用 0024 的原生会话搜索与分页，以及 0025 的运行期兼容策略。

## 项目定义

1. 第一版以 Codex 会话返回的 `cwd` 作为项目身份，不维护 Ariel 自有项目数据库，也不扫描本机目录。
2. 分组 key 使用规范化后的完整路径：去除非根路径末尾多余的 `/` 或 `\\`；保留大小写，不把不同完整路径但同名的目录合并。
3. 展示名取路径最后一段；根目录保留原根路径。完整路径同时显示，用于区分同名项目。
4. `cwd` 为空或无法形成路径标识时归入“未知项目”，但不得丢弃会话。

## 用户可见行为

1. 左侧会话区域改为“项目 → 会话”两级结构。每个项目标题展示项目名、完整路径和当前已加载会话数。
2. 项目顺序由其在当前 Codex 列表中首次出现的位置决定，因此继承原列表的最近更新时间顺序；项目内会话顺序保持原样。
3. 搜索结果也按项目分组；分页加载的新会话合并进已有项目或形成新项目，不重新按名称排序。
4. 会话仍是原来的选择入口，选中态、搜索摘要、更新时间、移动端侧栏收起和历史加载行为不变。
5. 列表标题同时显示当前已加载的项目数和会话数，避免分组后误解计数含义。

## 状态与安全边界

- 分组是 Web 对现有 `thread.list`／`thread.search` 结果的纯展示变换，不改变 Relay、Desktop Agent 或 Codex SSOT。
- 不读取文件系统，不推断 Git 仓库，不把目录名相同的路径视为同一项目。
- 本规格只建立项目导航；新增会话与目录选择作为后续独立规格实现。

## TDD 与验收

1. 纯函数测试覆盖：同 `cwd` 合并、不同 `cwd` 分离、同名不同路径分离、尾部分隔符规范化、根路径和空路径、稳定顺序。
2. Web 交互测试覆盖：侧栏渲染项目标题／路径／数量，会话仍可点击，搜索结果按项目分组。
3. 现有会话搜索、分页、移动侧栏、Web 全量测试和 production build 不回归。
4. 桌面和移动宽度均无横向溢出；物理手机最终视觉由用户复验。

## 非目标

- 不在本阶段枚举没有历史会话的目录。
- 不把 `cwd` 向上折叠到父目录或自动识别 monorepo 根。
- 不在 Ariel 中保存项目收藏、别名或排序。
