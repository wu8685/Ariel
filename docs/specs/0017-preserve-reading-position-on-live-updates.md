# 0017：实时更新时保留历史阅读位置

- 状态：Approved（用户于 2026-10-05 确认；0016 自动加载仍暂缓）。
- 来源：用户在手机向上阅读正在同步的会话历史时，新消息到达会把页面自动拉到最底部；希望取消这种抢夺阅读位置的行为。
- 范围：Ariel Web 的手机和桌面会话正文滚动容器；不改变原 owner、Relay 协议、0013 的最近 10 turn／手动“加载更早消息”、64 MiB 本机上限或发送行为。[0016](0016-scroll-triggered-history-loading.md) 的“上滑自动请求旧页”继续暂缓，本规格不启用它。

## 输入、输出与行为

1. 会话正文以自身 `.transcript` 为滚动容器。首次选择一条会话时，默认定位在已加载的最新消息；切换会话不得沿用上一条会话的滚动状态。同一会话重订阅时，若原可见 item 仍存在于新快照，尽量恢复它的阅读锚点。
2. 用户当前距离正文底部不超过 80px 时，视为正在跟随最新内容；新的 turn、回复片段或审批卡片到达后，正文可继续贴近底部。正文滚动必须局限于会话区，不得滚动整个页面或把输入框移出视口。
3. 用户主动上滑、使用滚轮／键盘进入距离底部超过 80px 的旧历史后，关闭自动跟随。此后新消息、运行状态更新或审批卡片到达，都不得把正文滚到最底部，也不得让正在阅读的可见内容跳位；同一位置可继续阅读。
4. 用户离开底部后若有新内容到达，显示紧凑、可访问的“回到最新”按钮，不遮挡消息、审批卡或输入框。点击它才滚到末尾并恢复自动跟随；用户自行滚回底部附近也恢复自动跟随并隐藏按钮。仅上滑而尚无新内容时，不用弹出新消息提示。
5. 继续使用 0013 的“加载更早消息”按钮。手动加载旧 turn 或旧 item、前插内容时保持原先可见消息的屏幕位置；分页完成后既不跳到更早页顶部，也不跳到最新末尾。用户可以再次手动加载，历史 cursor、去重、窗口释放和错误处理仍按 0013 执行。
6. 手机软键盘开合、视口高度变化、折叠／展开工具活动（若 0015 后续获批）不应重置“正在读旧历史”的状态；只因内容布局改变时尽量维持当前可见锚点。用户点击“回到最新”是明确例外。

## 错误与边界

- 正文为空、内容不足一屏时无需显示“回到最新”；滚动状态按底部处理。用户在流式更新时正好停在阈值附近，以实际滚动容器的当前距离判定，不用固定时间延迟猜测意图。
- 断线、Agent 重启或 stream 重同步后，旧视图和旧滚动锚点不得与**另一会话**混用；保留当前 thread 选择与草稿的既有恢复语义。同一会话新快照缺失原可见 item 时，明确回到最新并提示阅读位置无法恢复，不把旧 stream 的未确认消息当作新消息。
- 历史分页失败时维持已显示内容和阅读位置，现有错误提示继续可见；不能因失败反复自动请求或跳底。
- 滚动状态只保存在当前浏览器页面内存，不上传 Relay、不写业务持久化；不承诺刷新页面后恢复精确像素位置。

## TDD 与验收

1. 先写失败的 Web 测试：在底部时收到新 turn／流式片段会跟随；上滑超过阈值后收到同样更新不跳底，出现“回到最新”；点击或手动滚回底部后恢复跟随。
2. 先写失败的手动分页测试：前插一页 turn、补齐巨型 turn 的旧 item 后，原可见锚点位置稳定；分页错误、切换会话、重订阅和键盘视口变化不把旧锚点套给新视图。
3. Red 测试确实失败后再实现；Web 全量测试、构建和 Go 相关回归通过。在真实大会话的已订阅浏览器窗口与物理手机分别验证：停留旧历史时有新消息不跳底，点“回到最新”才到末尾；手动“加载更早消息”后阅读位置稳定。
