# 0123：刷新后恢复文件阅读现场

- 状态：Approved；用户于 2026-10-27 明确确认本规格，授权实现；部署仍需另行请求。
- 日期：2026-10-27。
- 用户需求：刷新当前 Web 页面后，保留文件阅读现场，不丢失多文件 Tab 和阅读位置。
- 关联：[0122 文件工作区](0122-minimizable-file-viewer.md)、0118 阅读模式、0119 Ariel 内置文件后端。
- 边界变更：0122 当前不保证刷新恢复，且 Tab 状态仅存在于内存。本规格获批后，允许浏览器当前标签页保存有界的文件阅读元信息；不改变文件正文仅使用内存缓存的边界。

## 1. 用户行为与范围

1. 同一 origin、同一浏览器标签页普通刷新后，恢复文件 Tab 的顺序、激活项、原版／Markdown 阅读／Diff 模式、各模式滚动位置，以及整体展开／最小化状态。
2. 原来最小化的工作区保持最小化，不抢占会话；原来展开的工作区在认证和设备核验后恢复文件视图。文件恢复不自行切换主会话、不创建会话、不发送消息、不重放引用或 mutation。
3. 已捕获的引用选区只保存 offsets 与版本证明，不保存片段文本；重读原文后 SHA 一致才重建。SHA 改变时清除旧选区和旧位置，按 0122 提示用户重新选择，不把旧范围映射到新内容。
4. Diff 位置仅在重读同一来源 turn／item 的 Diff 指纹一致时恢复；变化或不能确认时回到有效起点，保持 Diff 模式并提示，不显示旧 Diff 正文。
5. 只对当前展开文件按需读取，其他 Tab 先恢复轻量状态，激活后才读取；最小化时不预读正文。图片继续沿用 lazy 读取及外部图片显式许可，不恢复 Blob URL 或外部图片授权。
6. 本阶段只保证同一浏览器标签页刷新，不承诺浏览器关闭后重开、跨标签页同步、跨浏览器或跨设备恢复，也不保证离线刷新后仍可阅读正文。
7. 刷新后的原生浏览器高亮 Range 不重建；可核验的捕获选区及对应引用栏可恢复。文件菜单／搜索弹层不恢复，避免遮挡正文。

## 2. 保存内容与安全边界

使用当前 origin／当前标签页的 `sessionStorage`，新建独立版本化 key，不写 Relay、Desktop Agent、Chilling、数据库或正文日志。`sessionStorage` 是本地浏览器存储，不承诺加密保管或防止同 origin 脚本读取。

白名单 checkpoint 内容：

- schema 版本、保存时间、设备 ID 与 Agent epoch；
- Tab 的本地稳定 identity、顺序、来源 descriptor（thread／turn／item、相对 path 或受限 reference、source kind）；
- 激活 Tab、展开／最小化状态、原版／阅读／Diff 模式；
- 各模式滚动位置、已核验原文 SHA／Diff 指纹、捕获选区 offsets 和必要定位范围。

不得保存：

- 文件原文、Diff 正文、引用片段文本或任意工具输出；
- 图片二进制／data URI／Blob URL、外部图片允许状态；
- token、Passkey／Cookie、owner receipt、pending request、可直接执行的操作；
- loading／error／generation 等旧请求运行状态、任意未知输入字段或 DOM Range。

原有路径／引用／SHA／来源与 capability 校验继续有效。浏览器记录不是授权证明，不能凭缓存 descriptor 绕过 Desktop Agent 的来源核验；也不为了恢复而扫描任意路径。

## 3. 恢复顺序与隔离

1. 读取记录只解析元信息，不触发网络或向未认证界面展示文件路径；先做 schema／大小／字段类型／来源 union／SHA／有限数值及现有协议长度约束校验。未知版本或损坏记录丢弃并降级正常会话，不造成登录循环。
2. 认证通过后，确认保存的设备仍在当前授权设备列表中、Agent epoch 一致、所需文件能力仍获授权，才把 checkpoint 交给文件工作区。不得因初始设备／epoch 尚未知就覆盖或清空记录，也不得在用户已经手动选择新设备后迟到恢复旧现场。
3. 恢复过程需协调已有默认设备／会话恢复，先核对原设备，不因暂时默认选中了别的设备而恢复到错误机器。文件 descriptor 仍绑定原来源 thread；若当前主会话不同，可阅读但引用禁用，不改写 threadId。
4. 主动退出／断开、主动切换设备、授权范围撤销或确认的 Agent epoch 变化，清理内存和 checkpoint，并取消待执行保存／恢复。已清理的记录不得被迟到读取或 debounce 回调重新写回。
5. 临时网络中断、设备暂时离线、原地续登录不等于主动退出，不删除记录；恢复前重新核验。离线时显示明确等待／重试状态，允许最小化回到会话，不永远遮住会话。
6. 文件或来源失效只影响该 Tab，提供关闭／重试；不自动猜路径、不跳转登录、不影响其他 Tab 或主会话草稿。
7. 记录为 Tab 存续的辅助状态，不是文件 cache 或会话数据库。正文／Diff 仍使用现有 8 MiB／10 项共享内存 LRU；不增加 WebSocket、watch／follower 或后台文件轮询。

## 4. 写入、资源与错误

- Tab 打开／关闭／切换、模式、滚动、捕获选区与最小化状态均触发保存；正文缓存命中、streaming 或无关渲染不触发元信息变化。
- 常规写入最多每 250ms 合并一次；`pagehide`／页面转为隐藏时同步 flush 最新轻量状态。不能只订阅模型 revision，因为当前 reader 会直接更新滚动／选区锚点。
- 保存和恢复使用代次隔离，不新增轮询。正在恢复的空模型不覆盖尚未消费的 checkpoint；注销后的旧回调不能复活现场。
- 不设固定 Tab 数量上限；checkpoint 本身设 1 MiB 字节预算，读取前先限长。超过预算或浏览器 quota／禁用存储时，当前已打开文件不受影响；明确提示本次无法保存刷新恢复，不静默截断 Tab 或返回旧现场，尽力删除过时记录。
- TTL 暂定 7 天，沿用现有历史恢复的时间量级；有效交互／flush 更新保存时间。过期记录删除，不继续自动读取文件。
- JSON 校验与存储异常均有安全降级，不能阻断会话、发送或文件内存阅读；不把存储失败当作认证失败。
- 相同视口在正文／Markdown 完成准备后恢复滚动；视口或内容高度变化时将位置限制在有效范围，不承诺跨屏宽的像素级一致。

## 5. TDD 与验收

按获批范围严格 red → green → refactor。

| 行为 | 必须覆盖 |
| --- | --- |
| 普通刷新 | Chromium 实际 `reload`；多 Tab 顺序／激活项／展开与最小化、三模式和滚动恢复，原实现先失败 |
| 资源 | 至少 150 Tab 刷新后无丢失，只读激活项；最小化零正文读取，图片 lazy，不额外订阅 |
| 保存触发 | 独立滚动／模式／选区更新可落盘；debounce 与 pagehide flush，不依赖轮询或 DOM 卸载 |
| 版本 | SHA 一致才恢复选区；SHA／Diff 指纹变化清理旧状态；文件失效只影响目标 Tab |
| 无正文落盘 | 带特殊 fixture 正文／Diff／图片／片段哨兵，检查实际 sessionStorage 不含它们或凭据，仅含白名单 |
| 安全隔离 | 未认证零读取、不展示路径；设备／epoch／flag 不匹配不恢复，原地续登录可待核验，主动退出和迟到回调不复活 |
| 输入与容量 | 损坏／未知版本／超长／非法 offsets／重复 Tab／过期记录、quota／禁用存储均降级，不丢当前内存视图 |
| 竞争 | 恢复和默认选择／用户手动切换竞争；刷新时 pending read；清理后迟到响应；StrictMode 重入和重复恢复不重复读取 |
| 真实浏览器 | 320／390／1280px、短屏、文件菜单、引用栏、选区及模式恢复，行为＋几何断言，固定状态截图 |

同时保持 Web 单测、build、Go 与完整 Chromium 回归通过。测试仅使用隔离 fixture，不对真实 Codex 会话做写操作。物理 iPhone／Safari、强制终止进程／系统回收时的最后一瞬间保存不能用 Chromium 模拟冒充已验；部署仍需另行明确要求。
