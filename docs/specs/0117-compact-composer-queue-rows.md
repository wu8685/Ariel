# 0117：压缩输入区排队项的纵向留白

- 状态：Implemented（2026-10-27；与 0118／0119 联合实施，自动化验收通过，未部署）。
- 日期：2026-10-27。
- 范围：Web composer 上方排队列表的行密度，仅调整排队项布局。
- 关联：0031 后续输入队列、0038 双向拖拽与禁止误选文字、0116 统一圆形操作图标。
- 证据：[联合测试记录](../testing/2026-10-27-0117-0119-self-contained-files.md)；物理 iPhone／Safari 待用户复验。

## 1. 问题与目标

当前 `.queue-item` 在桌面／手机均有上下各 6px padding；内部手柄高 36／40px，手机操作按钮至少高 40px。按现有 CSS 计算，普通桌面行高为 49px，手机分隔行高为 53px、末行约 52px。单行摘要只有约 17–19px 高，按钮之外仍叠加 12px 纵向留白。

减少行内额外纵向 padding，将正常单行摘要（以及摘要＋一条辅助说明）的行高统一压到 **44px 内容区＋最多 1px 分隔线**。预计手机每项减少约 8px，桌面约 4–5px；不靠缩小字号、隐藏说明或重叠点击区域来压缩。

## 2. 输入与输出

- 输入仍为当前排队消息、摘要、截图计数、editable、运行／编辑／拖拽／disabled 状态。
- 输出仍为相同顺序、相同文字及相同操作入口；只减少排队列表占用的纵向面积，为对话正文留下更多空间。
- 无排队消息时仍不显示面板；不新增协议字段、状态、缓存或网络请求。

## 3. 布局与不变量

1. 排队项上下 padding 从 6px 改为 0；保留桌面左右 8px、手机左右 7px，以及现有列宽和横向间距。
2. 手柄和行内操作按钮提供实际 44px 高布局盒；行最小高度为 44px。非末行含 1px 分隔线，正常总高 45px；末行无分隔线，总高 44px。
3. 不使用负 margin、transform、绝对定位或溢出的伪元素缩小外框并扩大命中区域；相邻行的控件不能互相覆盖。保留现有按钮／手柄宽度，不进一步压缩横向点击范围或摘要空间。
4. 桌面摘要 13px、手机摘要 12px，现有 line-height、辅助文字、单行省略规则与 tooltip 保持不变。若截图计数与只读说明同时存在等情况需要更多空间，行高自然增长，不能固定高度裁切文字。
5. 不改变 0116 的 14／28／44px 圆形按钮 token；排队手柄和行内矩形操作不改造成圆形按钮，不修改 composer、header 或全局按钮样式。
6. 面板与输入框间距、暂停标题保持不变；不缩小暂停状态说明或隐藏辅助信息来伪造压缩效果。列表最大高度与内部滚动规则由 [0120](0120-scrollable-full-queue.md) 补充：完整渲染，约四行高，超出后内部滚动。
7. 保留展示文字不可选、编辑输入框和正文可选；上下拖拽、pointer capture／cancel、键盘排序、引导、删除、更多菜单及编辑回填语义均不变。

## 4. 边界与错误处理

- 长文字仍单行省略，截图与受限编辑说明可读；窄屏不能把右侧按钮挤到第二排或引入横向滚动。
- 高度变化后拖拽继续按 DOM 实际位置与行中点计算，不硬编码 44／45px 作为排序阈值。
- 菜单按新按钮位置定位并保持在 viewport 内；操作进行中继续沿用原有禁用与回执处理。
- 本次不改变 Codex queue SSOT、owner／epoch、出错／unknown 语义，不自动重试或重放请求。

## 5. TDD 与浏览器验收

1. 批准后先写并实际运行失败测试：排队项无纵向额外 padding，正常行高 44–45px，手柄和操作按钮实际高度至少 44px，多个辅助说明不被裁切。
2. Chromium 在 320／390／1280px 验证 1 项与 3 项队列、长摘要、截图说明、不可编辑说明、暂停／编辑／拖拽／disabled 状态；断言相邻目标不重叠、文字和按钮在行内、队列不遮挡 composer、页面不横向溢出。
3. 真实浏览器 viewport／touch 回归上下拖拽和跨文字长按，只提交一次完整新顺序、无文字选区；验证更多菜单、编辑回填及键盘排序仍可用。
4. 固定手机与桌面截图对照确认仅排队密度及其带来的正文可用空间变化，不批量接受未知截图差异；运行 Web 全量单测／浏览器测试及 production build。
5. 测试使用隔离 WebSocket fixture，不对真实 Codex 会话发送、删除或重排内容；物理 iPhone／Safari 仍需用户复验。
