# 0120 排队消息完整列表与内部滚动

状态：Implemented（2026-10-27；用户明确授权设计后直接实现、push 与双端部署；测试通过，发布另记）

证据：[测试记录](../testing/2026-10-27-0120-scrollable-full-queue.md)。物理 iPhone／Safari 待用户复验。

## 1. 目标与范围

当前 Web 使用完整 `queuedMessages`，没有四条截断；但暂停标题与列表分别限高，短 viewport 下内容可能超出外层面板，被输入区裁切。统一约束队列显示区域，保留所有排队项与既有操作。

本规格仅覆盖 Web 展示，补充 [0117](0117-compact-composer-queue-rows.md) 第 3.6 条；不改变 Codex 队列、Relay 数据与通信语义。协议已有的 64 项安全限制保持不变，不承诺无限提交排队消息。

## 2. 输入、输出与行为

- 输入：当前会话的完整排队数组、暂停状态、实际 viewport 与用户 pointer／touch／keyboard 操作。
- 输出：按原顺序渲染全部排队项，不以四项截断；标准行约四条高（列表最大 180px），窄高屏按 viewport 进一步收缩，超出部分在列表内纵向滚动。
- 超过四项显示紧凑提示“共 N 条 · 可上下滚动”；四项以内不额外占用提示空间。原有辅助读屏计数保留。
- 列表可通过 Tab 聚焦，使用浏览器原生方向键／PageDown／End 滚动，并提供可见焦点；拖拽手柄上的方向键仍用于排序。
- 从条目文字区域进行 touch 滚动，不误触发排序、不选中文字；手柄拖拽与菜单操作继续作用于完整队列。

## 3. 布局不变量与边界

1. 面板采用纵向 flex，暂停标题与计数提示不收缩，列表 `min-height: 0` 并在剩余区域内滚动，三者总高度不超出面板。
2. 保留实际至少 44px 的操作盒及正常 44–45px 行高，不缩小字号或裁切辅助说明。最后一项滚动到末尾后可完整显示并编辑。
3. 面板与输入框不重叠，输入框与操作栏保持可见；不引入页面横向溢出，滚动不串到会话正文。
4. 0 项不显示面板；1–4 项沿用紧凑展示；5–64 项均可访问，不创建额外订阅、请求或历史读取。
5. 跨 viewport／运行或暂停状态继续有效；菜单沿用现有固定定位与滚动关闭策略。
6. 不新增拖拽自动滚动，不改后端队列容量、编辑／删除／引导语义、错误处理或 mutation receipt。
