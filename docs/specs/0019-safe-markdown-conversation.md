# 0019：安全呈现会话 Markdown

- 状态：Implemented（用户于 2026-10-05 明确授权免再次确认；Web 自动测试与隔离浏览器通过，物理手机待复验）。
- 来源：会话正文目前用纯文本节点呈现，Markdown 标记和链接不会变成对应排版或可点击元素。
- 范围：Ariel Web 的手机、桌面共用会话正文；不改变原 Codex 文本、协议、owner、历史分页、发送语义或 0015 工具详情。沿用 0018 的黑色 Night 主题与左右气泡、0017 的阅读位置规则。

## 输入、输出与不变量

1. 仅对 `user` 和 `assistant` 的非空 `item.text` 解析 Markdown。支持 CommonMark 的段落、h1–h6 标题、粗体、斜体、引用、行内代码、围栏代码块（可标语言但不执行／下载高亮器）、有序与无序列表、分隔线、转义字符；支持 GFM 的删除线、表格、任务列表、裸 URL 和脚注。脚注锚点按消息隔离，不能跨气泡串跳。聊天正文中的单个换行尽量保持可见，不把原先可读的换行压成一整段。
2. `system`／未知兼容性提示、审批及补充问题、工具活动的标签／参数／输出／diff 均维持纯文本，不经 Markdown 或 HTML 解释。user／assistant 原文不得被改写或存为派生正文；流式更新与历史分页对同一文本应用相同投影。
3. 允许可点击的 `http:`、`https:`、`mailto:` 外部链接以及同页片段。外部链接在新标签打开，并带 `noopener noreferrer`；其他协议、相对路径、协议相对 URL、凭据 URL 及控制字符混淆地址不产生可导航链接，链接文字仍可读。点击是用户显式动作，渲染本身不请求链接目标。
4. Markdown 图片不生成 `<img>`，只显示中性的“图片：alt 文本”占位；alt 缺失时显示“图片”。不自动加载 `http(s)`、`data:`、相对或本地文件资源。原生 HTML 一律忽略，不生成 HTML 元素、事件处理器、iframe、视频、表单或脚本；不用 `dangerouslySetInnerHTML`、`rehype-raw` 或可执行插件。
5. 消息中的代码、长链接、宽表格、长英文词和多层列表不得撑破气泡或页面。表格在气泡内部横向滚动，代码块可独立横向滚动；手机 390px 与桌面宽度都保持发送按钮在视口内。Night 配色下正文、链接、代码、引用、表格及 focus 状态可辨识，链接不能只靠颜色识别。
6. 为防巨型 item 在手机上阻塞渲染，单条正文超过 256 Ki UTF-16 code unit 时退回原文纯文本，并明确显示“内容过长，暂以纯文本显示”；不能截断内容。语法尚未完成的流式片段可按当下可解析的部分显示，后续片段到达后重新投影；解析失败时同样保留全文纯文本并显示降级提示，而非使会话空白。

## 错误、边界与验收

- Markdown 只作为显示投影，不从正文中生成新的 Ariel 操作按钮，不自动执行代码、读取本地文件、获取远程图片或解析不受信任的 HTML。链接可跳转外站，用户需主动点击。
- 数学公式、Mermaid、嵌入媒体、语法高亮、附件下载与相对仓库文件导航不在本规格内；不伪装为已支持。
- 先写并运行失败的 Web 测试：用户／Codex 的常见 Markdown 与 GFM 成为语义元素、链接白名单及安全属性、原生 HTML 和图片不触发资源加载、工具／system／审批仍为纯文本、超长与畸形输入降级保留原文、手机窄屏不溢出。再做最小实现，运行 Web 全量测试与构建、Go 回归。
- 在只监听本机的隔离 Mock 会话中，用浏览器检查手机与桌面宽度的标题、列表、链接、宽表格和代码块；真实 Desktop 历史只做只读查看，物理手机由用户复验。不得为了验收往业务会话发送测试 Markdown。
