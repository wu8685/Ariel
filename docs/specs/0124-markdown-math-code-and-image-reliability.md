## 1. 用户行为

1. 打开包含公式的回复或 Markdown 文件阅读模式时，行内公式和独立公式正确排版，不直接露出反斜杠命令；原版模式仍展示未经改写的 Markdown。
2. 围栏代码中的伪代码使用清晰的等宽字体、稳定的空格与 Tab 缩进、统一的行距和背景。长行只在代码块内滚动，不撑宽整页，也不自动改写算法内容。
3. 文件图片进入阅读区域附近时按需加载；加载、失败、不支持、未授权有不同提示。失败后可在原位置重试，不必关闭文件、重新登录或刷新整个会话。
4. 会话中已匹配原生图片的引用继续走原有受限图片入口；普通公网 HTTPS 图片不再是无操作的占位，用户看到域名并主动允许后才加载。
5. 保留文件 Tab、最小化、模式选择、阅读位置与显式引用到会话。选择文字不自动跳回会话，图片加载不重置草稿或会话订阅。

## 2. 已确认事实与未确认项

### 2.1 本地复现与代码证据

- 两套 Markdown 渲染器目前只接入 GFM，没有数学解析与排版。只读 SSR 检查确认 `$x^2 + \frac{a}{b}$` 仍保留原始命令，`\[...\]` 的反斜杠会被普通 Markdown 转义消费，没有数学 DOM。现有问题不能笼统称为字符编码错误。
- 同一检查确认围栏代码的四空格、八空格缩进仍保留在输出中。因此尚无证据认为解析器删除了缩进；当前两处代码样式不一致，也没有明确的 Tab 宽度约束。
- 未匹配原生图片的会话 Markdown 图片明确生成 `markdown-image-placeholder`，没有图片节点或加载操作。这是当前设计限制，不是网络请求已经失败的证据。
- 文件阅读已有来源受限的本地资源读取与外链显式许可。当前失败占位缺少就地重试，本地 Blob 图片也没有浏览器加载／解码失败状态；可见性变化会取消读取并清空显示，需要进一步用慢响应、滚动和重渲染复现是否出现长期占位。

用户尚未提供出错内容样例；具体公式语法、伪代码是否使用围栏、图片地址类型及目标环境仍待核实。图片故障不能在缺少证据时统一归因为网络、权限或 lazy 生命周期。

## 3. 输入、输出与不变量

- 输入：已有消息文本或已授权文件原文、原文位置、文件 SHA／来源、当前资源能力与 Agent epoch、用户图片许可和重试操作。
- 输出：数学 DOM、安全的代码排版、受限图片及局部状态；可靠映射回原始文件的引用或明确的不可引用提示。
- 原始消息和文件是 SSOT。只改变 Web 展示，不改写 Markdown、不保存派生正文、不更新真实文件、不发送会话消息。
- 不新增 WebSocket、后台轮询、会话刷新、per-Web follower 或 Relay 图片缓存；最近两个 turn 与 5 秒 streaming 节奏保持不变。
- 基础能力归 Ariel，不依赖 Chilling。默认复用已有资源协议；若复现证明需要新增来源类型或协议，先修订本规格并重新确认，不能靠 Web 拼路径绕过。
- 公式、代码及图片不能扩大为任意 HTML／JSX／脚本／事件处理器／iframe 的执行入口。

## 4. 数学公式

1. 两处显示使用一致的受限数学解析与 KaTeX 排版，覆盖 `$...$`、`$$...$$`、`\(...\)` 和 `\[...\]`。括号式定界符在 CommonMark 转义之前识别，不全局替换反斜杠。
2. 围栏代码、行内代码、转义定界符、普通金额与不完整 streaming 片段不得误判为公式。测试至少包含单个 `$20`、同段多个金额、含美元符号的代码，以及补齐后从原文变为公式的片段。
3. 常见分式、上下标、根式、矩阵、求和与多行公式可辨识。行内公式遵循基线；宽独立公式在自身容器内横向滚动，不裁切右侧、不撑宽页面。
4. 不接受公式中的任意链接、HTML、样式注入或资源下载；禁用受信任宏能力。字体和 CSS 随 Ariel 静态资源发布，不依赖外部 CDN，不把公式变成图片上传给第三方。
5. 单公式原文最多 16 Ki UTF-16 code unit，单份渲染最多 256 个公式，宏展开最多 1000 次；超限、不完整或解析错误只对该部分降级为可读原文与局部提示，不清空全文或使页面持续 loading。
6. 保留现有单份 256 Ki UTF-16 code unit 阅读预算与错误边界。数学依赖按需要拆包，不让普通登录／不含公式的内容为公式提前请求字体。
7. 数学生成 DOM 不能作为可直接引用的文件原文。能够证明连续原文区间时引用对应 TeX；否则禁用该选区提交，提示切到原版精确选择。跨越公式的选区不得拼接出并不存在的原文。

## 5. 伪代码与围栏代码

1. 共用可维护的代码块排版规则：明确的等宽字体、`tab-size: 4`、稳定行距、适度内边距与深色主题对比。代码字体不随文件正文的比例字体漂移。
2. 保留空格、Tab、空行与多层缩进；不对原文 trim、重新缩进、自动格式化或删除空行。复制／引用仍返回原始内容。
3. 支持已有围栏及 `text`／`plaintext`／`pseudocode` 等语言标签的清晰显示；未知语言保留可读等宽内容。不执行代码，不为了高亮下载任意语言插件。
4. 不将一般自然语言或列表猜成伪代码。未使用围栏的样例需先核实，再决定是否只是原文需要按标准 Markdown 标记。
5. 保留 Mermaid 的既有渲染路径；普通代码不经过 Mermaid，也不能被数学解析改写。
6. 代码块内部横向滚动，手机触摸可操作；页面与文件页不横向溢出。保留文件原版的既有软换行，本节不改变原版／Diff 规则。

## 6. 图片可靠性与来源

### 6.1 文件阅读

- 标准 Markdown 内联与引用式相对图片继续按父文档目录解析，包括中文、空格、URL 编码及 workspace 内合法的 `../`；资源必须确实被同一 SHA 的父文档引用。
- 保留 PNG／JPEG／GIF／WebP、4 MiB／12 MP／8192px、两张并发、32 项等待和 16 MiB 图片缓存限制。原版、Diff、非激活 Tab、最小化文件页不预读图片。
- 区分等待进入可见区域、读取中、浏览器解码中、成功、失败／拒绝。成功必须由浏览器确认，不将分块完整或创建 Blob URL 当作图片已能显示。
- 对 transient 读取失败提供显式重试；不无限自动重试，不重新拉全文或重连会话。来源已变化时提示重新核验父文档，不能用旧 SHA 重试新文件。
- 滚动离开、Tab 切换或非图片内容的重渲染不得导致加载结果反复丢失。允许离屏取消或释放，但需有稳定的占位尺寸与状态，回到视口能正确重获资源，不陷入观察回调／取消循环。
- 已在当前 Session 中验证并缓存的图片允许在模式恢复时直接重获内存 lease，不等待新的 viewport 请求；这不允许预取未读取的离屏图片。局域网缺少 Web Crypto 时使用本地有界 SHA-256 兼容路径，不能跳过 digest 校验。
- Blob URL 在 DOM 不再使用时才能回收；关闭／切设备／epoch 变化取消 pending，晚到结果不能落到另一个文件。StrictMode 重入、模式来回切换和缓存复用须可用。
- 临时网络中断、缺失能力、找不到文件、类型／大小／digest／解码失败分别局部提示；没有可靠来源时不得尝试任意路径或调用 Chilling。

### 6.2 会话与外链

- 已匹配 native 图片 metadata 的会话引用继续走 `thread.image` 与原来的显式加载策略，不把图片塞回 streaming snapshot。
- 新增普通公网 HTTPS Markdown 图片的域名可见许可与加载／失败／重试入口；首次渲染和未授权时不触发资源请求。授权仅在当前文档／当前消息版本内存中有效，不随 0123 checkpoint 保存，也不跨内容变更自动沿用。
- 外链由浏览器按需加载，设置 no-referrer，不附加 Ariel token 或 Authorization；不由 Relay／Agent 访问外网，不提供通用代理绕过目标站点、防盗链、CSP 或浏览器策略。失败保留 alt、域名和重试。
- 继续阻止 HTTP mixed content、协议相对 URL、用户信息 URL、危险协议及已知本机／内网地址。SVG、HTML img 和未获批准的嵌入格式不直接执行。
- 文件中的受限 raster data 图片继续走现有预算。会话中未匹配 native metadata 的 data 图片、本地绝对路径或相对路径不得凭文本猜测授权；显示明确的“不支持此图片来源”，不再只留下无解释占位。
- Obsidian wikilink、原生 HTML img、需登录的外部图片尚不列为已支持；若用户样例使用这些格式，先给出实测结果并补规格，不在缺少来源证明时伪造成功。
