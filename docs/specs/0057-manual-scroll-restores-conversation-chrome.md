# 0057：手动滚到最新时可靠恢复会话界面

- 状态：Implemented（单元测试、真实移动 Chromium、关键几何与截图已验）。
- 范围：会话 transcript 的滚动方向识别、触摸／滚轮意图、折叠界面恢复、移动端真实浏览器回归。
- 关联：[0045 阅读历史时自动收起会话 Header](0045-collapse-conversation-header-while-reading-history.md)、[0053 回到最新时稳定恢复会话界面](0053-stable-latest-chrome-restoration.md)。

## 问题

折叠状态当前只在“本次 `scroll` 事件的 `scrollTop` 比上次至少增加 1px”且底部距离不超过 32px 时恢复界面。移动 Safari 的惯性滚动、亚像素滚动或 transcript 高度变化可能把最后一次跨入 32px 区间的增量压到 1px 以内；此时用户已经明确向最新方向滚动并到达底部，单次事件却被当成没有方向，Header 与输入区域继续保持折叠。点击“回到最新”绕过这项单事件方向判断，所以能够恢复。

## 用户结果

用户手动向最新消息滚动并抵达底部附近时，Header 与输入区域应与点击“回到最新”一样可靠地恢复；恢复过程继续保持底部锚定，不重新出现抖动。即使折叠后视口扩张使 transcript 已没有可继续滚动的距离，用户在底部继续向最新方向滑动或滚轮操作也能表达恢复意图。

## 行为契约

1. 折叠状态不再只看单个 `scroll` 事件是否超过 1px；系统应在一次连续操作中保留最近的滚动方向意图。
2. 任意正向 `scrollTop` 增量表示向最新消息移动，负向增量表示返回较早历史；零增量保留既有意图，避免最后一个亚像素／边界事件丢失方向。
3. 手机触摸向上滑动、鼠标滚轮／触控板向下滚动显式标记“前往最新”意图；反向手势清除该意图。
4. 当显式意图存在且底部距离不超过 32px 时，复用既有 `restoreLatestChrome`，展开 Header 与输入区域并进入 260ms 布局稳定窗口。
5. 仅由折叠导致的视口扩张或 streaming 内容变化不得自行恢复界面；必须存在用户向最新方向的滚动或手势意图。
6. 切换会话、程序化回到最新和恢复完成后清理旧方向意图，不能把上一段操作带入下一次阅读。

## 验收

1. 单元测试复现“先向最新大幅滚动但仍在 32px 外，最后以小于 1px 的增量跨入恢复区间”，修复前保持折叠，修复后恢复。
2. 单元测试覆盖 transcript 已在底部且无法继续改变 `scrollTop` 时，用户继续向最新方向的触摸手势可以恢复；反向手势不能恢复。
3. 390×844、touch-enabled 的真实 Chromium 用多段亚像素滚动复现并验证恢复；观察 550ms，界面只发生一次 `true → false`，Header 为 66px、输入区可见、底部距离接近 0。
4. 保留 0045／0053 的全部折叠、滞回、streaming 阅读位置和防抖回归；运行 Web 全量单测、Playwright 与 production build。
5. Chromium 只能验证浏览器行为模型；物理 iPhone/Safari 仍由用户最终复验。

## 实现结果

Web 现在跨多个 `scroll` 事件保留最近的滚动方向；最后一步即使只有 1px，也不会丢失此前明确的“前往最新”意图。transcript 同时监听 wheel 与 touch 方向，在已经到达滚动边界、`scrollTop` 无法继续变化时仍可恢复。恢复期间只有反向用户手势才会退出底部锚定，布局自身产生的 `scrollTop` 调整不会再被误判为用户上滚。完整证据见 [0057 验收记录](../testing/2026-10-08-0057-manual-scroll-restores-conversation-chrome.md)。
