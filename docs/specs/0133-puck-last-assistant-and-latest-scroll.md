# 0133：Puck 恢复最近助理与对话默认定位最新消息

- 状态：Approved（2026-11-06；用户在第 35 轮明确给出行为、边界与验收要求，并要求直接实现）。
- 日期：2026-11-06。
- 关联：0130（Puck 个人助理）、0132（Puck 浮动 header 与 composer）。

## 1. 用户结果

1. 打开、刷新、重新登录后进入或从其他 workspace 返回 Puck 时，恢复本浏览器最近使用的助理，不再固定打开列表第一项。
2. 首次打开或切换助理后，对话默认显示最底部的最新消息。
3. 用户在当前助理中主动上滚阅读历史后，后续实时消息或轮询结果不得强制抢回底部；用户回到底部后恢复跟随。
4. 浮动 composer 不遮挡最后一条消息。

## 2. 输入与持久化

- 最近助理以 `assistantId` 写入 Web `localStorage`，仅作为当前浏览器的界面偏好，不新增 Relay／Desktop Agent 协议或服务端状态。
- 明确切换助理、创建并进入助理、发送消息时，均将该助理记为最近使用。
- `localStorage` 不可用、读写抛错或值为空时，Puck 仍可正常打开。

## 3. 选择与恢复行为

1. `puck.list` 首次返回后，按以下顺序选择：
   - 当前仍有效的已选助理；
   - `localStorage` 中仍存在于列表的最近助理；
   - 列表第一项；
   - 空列表时不选择助理，显示既有空状态。
2. 最近助理已删除或不存在时，回退列表第一项，并用回退结果修正本地偏好；不得出现空白或黑屏。
3. 轮询刷新助理列表时，当前有效选择优先，不能被本地旧值切走。
4. 既有按 `assistantId` 隔离 history／watch／send 回执的规则保持不变。

## 4. 滚动行为

1. transcript 的“跟随最新”状态在首次选择、切换助理以及用户主动发送消息时开启。
2. 开启时，在 React 提交当前消息后将 `scrollTop` 设置为 `scrollHeight - clientHeight`；历史异步返回、问候或处理中消息陆续到达时继续落在底部。
3. 用户滚动后，距底部超过小范围阈值即关闭跟随；回到底部时重新开启。
4. 跟随关闭后，同一助理的新 history／watch 消息不得改变当前 `scrollTop`。
5. 切换到另一助理必须重新开启跟随并落到底部，不继承上一助理的阅读位置。
6. 浮动 composer 高度变化时，若仍在跟随最新，应重新定位底部；既有基于 composer 高度的 transcript bottom padding 保持有效。

## 5. 错误处理与兼容性

- 偏好恢复是 best-effort；存储错误不得阻止助理列表、历史或 composer 工作。
- 不改变 Puck 视觉、Passkey、drawer、头像、发送、消息卡片或协议语义。
- 不做跨设备同步；本轮不新增服务端 preference API。

## 6. 验收标准

1. Vitest 证明：有效最近助理被恢复；失效记录回退并修正；切换后 history 渲染完成时位于底部；手动上滚后同助理新消息不抢滚动。
2. Playwright 在真实 Chromium viewport 中证明：刷新式打开恢复最近助理；首次打开与切换助理均位于底部；最后一条消息不被浮动 composer 遮挡；手动上滚后轮询新增消息不抢滚动。
3. `npm test` 与 `npm run build` 通过。
