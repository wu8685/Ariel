# 0090 文件查看器导航、双视图与片段引用

- 状态：Implemented（2026-10-17；用户已完成实际使用验收）
- 日期：2026-10-17
- 影响范围：Ariel Web
- 前置规格：`0089-turn-file-links-and-selection-context.md`

## 1. 背景与目标

当前文件内容页存在四个交互问题：

1. 长行使用横向滚动展示，手机端需要左右拖动才能阅读完整内容。
2. 行号是引用入口，点击后会直接引用整行并离开文件页；用户无法稳定选择行内片段，也无法在确认引用前继续检查选区。
3. 文件页缺少语义明确的返回入口，右上角关闭符号不足以表达“返回当前会话”。
4. 文件卡只有一个入口，虽然 Chilling 已返回该 turn 的有界 diff，Web 却只能展示当前工作区版本，无法直接检查本次修改。

本规格将文件内容页调整为适合窄屏阅读、变更检查与精确引用的交互：文件卡提供“看原文 / 看 Diff”入口；文件页提供明确的返回按钮；长行按可用宽度软换行；用户可选择原文中的任意连续文本，只有显式点击右下角“引用到会话”后，才提交引用并返回当前会话。

## 2. 输入与输出

### 2.1 输入

- Chilling 返回的文件内容、路径、digest 与行范围。
- Chilling 随 file change 返回的有界 `diff` 与 `diffTruncated`。
- 用户从文件卡选择“看原文”或“看 Diff”。
- 用户通过鼠标、触摸或键盘建立的原生文本选区。
- 用户点击“返回会话”“引用到会话”或关闭文件内容页的操作。

### 2.2 输出

- 自动换行且无需横向滚动的文件内容视图。
- 使用 unified diff 语义着色的本次变更视图。
- 与原始文件内容精确对应的选中文本及起止行号。
- 经用户确认后加入当前会话 composer 的文件引用 chip。

## 3. 行为规范

### 3.1 文件卡的双入口

1. 每个可查看的 file change 在路径右侧提供两个独立操作：
   - “看原文”：打开当前工作区版本；
   - “看 Diff”：打开该 turn 记录的 diff。
2. `update` 类型默认同时支持两个入口。
3. `add` 类型同时支持两个入口：“原文”为当前新增文件，“Diff”为新增行视图。
4. `delete` 类型没有当前工作区原文，“看原文”不可用；只允许查看该 turn 已返回的 Diff。
5. `diff` 为空时，“看 Diff”显示为 disabled，不得临时调用 Git 或从当前文件反推历史 diff。
6. 点击“看 Diff”直接使用 `file.context.changes` 已返回的有界 diff，不为此预读完整文件；点击“看原文”才调用 `file.context.read`。
7. 两个操作必须具有独立的可访问名称和至少 44×44 CSS px 的移动端触控区域，不把整行同时做成第三个含义不明的点击入口。

### 3.2 文件页导航

1. 文件页 header 左侧提供带返回箭头和“返回会话”语义的按钮。
2. 点击返回按钮关闭文件页并恢复打开前的同一个会话，包括：
   - 会话滚动位置；
   - composer 草稿；
   - 图片、文件引用等尚未发送的附件；
   - 当前会话 identity。
3. 返回操作不得提交当前选区，不得发送消息，也不得触发整段会话重新同步。
4. 手机全屏页必须始终显示该返回按钮；桌面侧边面板可同时保留右上角关闭按钮，但两者行为一致。
5. 浏览器 Back 在文件页打开期间应优先关闭文件页并返回会话，不得直接离开 Ariel；如果当前实现未把文件页写入 browser history，则不得为此伪造会话路由，本规格至少保证显式返回按钮可用。

### 3.3 原文与 Diff 视图

1. 原文页标题标明“当前工作区版本”；不得把它描述为该 turn 发生时的历史快照。
2. Diff 页标题标明“本次修改”，并展示路径和 change kind。
3. Diff 按 unified diff 的行语义呈现：新增、删除、hunk header 与上下文行有可辨识但不过度刺眼的颜色；未知格式按普通等宽文本安全降级。
4. Diff 中的长行同样软换行，软换行不得改变 `+`、`-`、空格等原始前缀。
5. `diffTruncated = true` 时，在 Diff 页显示“Diff 已截断”提示，不得让用户误以为内容完整。
6. Diff 视图为只读检查视图，可以进行浏览器原生选择和复制，但本版本不提供“引用到会话”：删除行和 hunk metadata 无法通过现有 Chilling selection contract 映射为当前文件的合法行号与 digest。
7. 同一个 file change 同时具备原文和 Diff 时，内容页 header 提供“原文 / Diff”切换控件；切换不返回会话，也不重复请求已经取得的数据。

### 3.4 长行自动换行

1. 文件内容默认按查看器可用宽度软换行，不提供阅读正文所需的横向滚动。
2. 换行只改变显示，不得修改文件内容、空白字符、引用文本、行号、digest 或后端请求参数。
3. 原始缩进与连续空格应保留。
4. 对没有自然断点的超长 token、URL 或字符串，允许在任意字符处断行，避免撑宽页面。
5. 行号固定在 gutter 中，并与该原始行的第一条视觉行对齐；软换行形成的后续视觉行不得生成新行号。
6. viewport 尺寸、设备方向或面板宽度变化时，内容应重新排版，不得因此丢失已记录的选区。

### 3.5 内容级选择与高亮

1. 用户可以选择任意连续文本，包括：
   - 单行内的一部分文字；
   - 跨行片段；
   - 重复出现的相同文字中的某一次实际选区。
2. 选区必须根据 DOM 中的真实起止位置计算，不能使用 `content.indexOf(selectedText)` 推断位置。
3. 有效选区使用浏览器原生 selection 高亮；高亮颜色应在当前深色主题下清晰可辨。
4. 行号仅用于定位，不再是可点击的整行引用按钮。
5. 仅完成文本选择时，文件内容页保持打开，不自动返回会话，也不自动创建引用。
6. 用户建立新的有效选区后，用新选区替换旧选区；空选区不应意外覆盖最后一次有效选区。

### 3.6 显式“引用到会话”

1. 原文视图右下角固定提供“引用到会话”按钮；没有有效选区时按钮为 disabled。Diff 视图不展示该按钮。
2. 点击按钮后才执行以下动作：
   - 将路径、起止行号、digest 与精确选中文本加入当前会话的引用上下文；
   - 关闭文件内容页；
   - 返回打开该文件前的同一个会话与 composer；
   - 聚焦 composer，但不得自动发送消息。
3. 关闭按钮只关闭内容页，不提交尚未确认的选区。
4. 引用 chip 的删除、消息发送和上下文序列化规则继续遵循 0089，不改变 Chilling API 与安全边界。

## 4. 不变量与边界条件

1. 文件正文仍由 Chilling 按既有 allowlist、workspace root、symlink 与大小限制读取。
2. Ariel Web 不缓存完整文件正文到会话记录；刷新后的恢复行为沿用 0089。
3. 选中文本必须与原始 `file.content` 的连续切片一致，不能混入行号、按钮文案或布局产生的额外空白。
4. 跨行选区的起止行号按原始文件换行符计算；软换行不计作新行。
5. CRLF 与 LF 文件均应得到正确的文本和行号。
6. 文件内容为空、选区仅发生在正文之外、selection 跨出查看器，均视为无新的有效选区。
7. 浏览器缩放和手机窄屏下不得出现由正文长行造成的页面级横向溢出。
8. Diff 是 Codex turn 中记录的修改证据；原文是读取时的当前工作区版本。两者可能因后续修改而不一致，Web 必须明确标注，不能合并成一份伪历史快照。
9. Diff 最多使用 Chilling 已执行的 64 KiB 有界结果，不在 Relay 或 Web 重新访问 Git、文件系统或 Codex 私有 IPC。

## 5. 错误处理

1. 文件读取失败继续使用现有文件页错误态，不生成引用。
2. 选区无法映射回原始内容时，保留文件页并提示用户重新选择，不得提交推测出的片段。
3. 引用提交失败时，保留文件页和选区状态，允许用户重试或关闭。
4. Diff 缺失时禁用 Diff 入口；Diff 被截断时展示明确提示。两种情况都不得影响原文读取。

## 6. 可访问性

1. 正文保留原生文本选择能力，不用不可访问的点击覆盖层模拟选区。
2. “引用到会话”按钮有明确的 disabled 状态与可访问名称。
3. 键盘用户能够聚焦正文、选择文本并触发引用按钮。
4. 行号不进入引用文本，并应避免被辅助技术误认为可执行操作。
5. 返回按钮、“原文 / Diff”切换和文件卡双入口均支持键盘操作、可见 focus 状态与明确的 screen-reader label。

## 7. TDD 验证计划

实现必须按 red → green → refactor 执行：

1. 单元测试先覆盖：
   - 单行部分选区；
   - 跨行选区；
   - 重复文本中的第二处选区；
   - CRLF 行号计算；
   - selection 跨出正文时拒绝更新；
   - 选择文本时不关闭文件页，显式点击按钮后才提交并返回。
   - update／add／delete 三种 kind 的入口可用性；
   - Diff 缺失与 `diffTruncated` 状态；
   - 返回操作不提交选区。
2. 真实浏览器测试先覆盖：
   - 固定手机 viewport 下长行自动换行且正文无横向 overflow；
   - 鼠标/DOM Range 建立部分选区后按钮可用；
   - 点击行号不会引用或关闭页面；
   - 点击“引用到会话”后出现精确引用 chip，composer 未自动发送；
   - 关闭文件页不会提交选区。
   - 返回按钮回到原会话，并保留滚动位置、草稿和附件；
   - “看原文 / 看 Diff”进入正确视图，内部切换不重复请求；
   - Diff 新增／删除／hunk 行语义着色，长行无横向 overflow；
   - 手机 viewport 下两个文件入口与返回按钮满足触控尺寸。
3. 以固定手机 viewport 截图验证 gutter、软换行、选区高亮和右下角按钮的层叠关系。

## 8. 验收标准

1. 手机端打开包含超长行的文件，不需要左右拖动即可阅读全部内容。
2. 用户能准确高亮单行中的任意一部分文字，而非只能选择整行。
3. 选择文本本身不会离开文件内容页。
4. 只有点击右下角“引用到会话”后才返回原会话，并出现内容准确的引用 chip。
5. 相同文本重复出现时，引用的行号与片段仍对应用户实际选择的位置。
6. 文件页有明确的返回按钮，返回后仍是原会话，且草稿、附件和滚动位置不丢失。
7. 修改文件可以分别进入当前原文和该 turn 的 Diff；删除文件仍能查看 Diff，且不会冒充存在当前原文。
8. 截断 Diff 有明确标记，Diff 与当前原文的时间语义不会混淆。
9. 现有文件读取安全限制、会话发送流程和其他移动端交互回归测试全部通过。
