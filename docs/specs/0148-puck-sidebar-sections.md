# 0148：Puck 侧边栏分组

- 状态：Implemented（2026-11-10；建群在加号菜单，建分组改为空白处右键，侧边栏可按名称搜索）
- 日期：2026-11-10

## 范围

侧边栏分组是整理 Bot 和群聊的文件夹，不是 `puck.group` 的多人聊天。建群仍只创建会扇出给成员大脑的会话，入口在侧边栏加号菜单里。

默认分组是虚拟的「未分组」。没有 placement 的 Bot 和群聊都在这里。它不能删除，也不能改名。用户创建的分组可以改名、收起和展开。

## 行为

1. 用户可以新建、重命名、收起或展开分组，并把单个 Bot 或群聊移入某个分组，或移回「未分组」。
2. 删除分组只清除该分组记录，并把里面的 placement 改回空分组。不得删除 Bot、群聊、消息或历史。
3. 分组、顺序和收起状态写在现有 Puck SQLite，schema 7。Relay 是单 owner 的 Passkey 实例，因此这份库就是 owner 范围的服务端存储。不另建一套分组概念，也不把分组写入 Web localStorage。
4. 收起状态随 `puck.section.list` 恢复，刷新后保持。
5. 行上没有分组下拉。按住约 450ms 后拖到目标分组的标题或列表上才移动；未到时间就移动视为滚动，松手在分组外则取消。拖动时原行变淡，并有跟随手指的浮层，目标分组高亮；停在收起的分组上会自动展开，靠近列表边缘会自动滚动。分组标题用右键或长按打开重命名和删除，未分组没有这两项。
6. 移动或收起不改变当前选中的会话，不清除未读，也不改最后助手恢复。
7. 新建分组不作为顶栏主按钮，也不和「建群」并排。在左侧栏空白处右键（不点在 Bot、群聊或分组标题上）打开菜单，其中一项是「建分组」。分组标题的右键和长按仍只提供重命名和删除。
8. 顶栏加号打开菜单，里面是「新建助理」和「建群」。加号左侧是放大镜。点开后按名称过滤 Bot；群聊名称命中时一并显示。清空或按 Esc 恢复原来的侧边栏，不改变分组的收起状态。

## 限制

1. 一个 Relay 进程一份 Puck 数据库。这里没有多租户分组表；访问隔离沿用现有 Passkey 会话。
2. 分组最多 20 个，名称最多 24 个字符。顺序用 placement 的 position 保存，移动时追加到目标分组末尾。
3. 容器重建或数据库文件被替换后，分组和收起状态会丢失。进程重启不会丢失。
