# 0149：Puck 头像页对齐 Grok Bot

- 状态：Implemented（2026-11-10；用户要求按 Grok Bot 头像截图实现）
- 日期：2026-11-10

0147 的 13 个带眼睛形状、11 色（白色起头）和「普通头像不画存在光环」继续有效。本文只改选择器的页面结构和排列。不改侧边栏分组、长按拖动、Passkey，也不改头像选项数量。

## 输入

权威依据是 Grok Bot 的「头像」页截图：

1. 独立的头像页，而不是助理信息里随容器宽度折行的选项区。
2. 顶栏是返回、标题「头像」和「完成」。
3. 三个页签：「形状」「生成」「上传」。「形状」为选中页签。
4. 大预览在页签下方。
5. 卡片内形状是固定的 4 + 4 + 5，不按容器宽度改成 6 + 6 + 1 或 5 + 5 + 3。颜色仍是 6 + 5，白色在第一格。
6. 选中形状沿外轮廓描一圈 `#656569`。选中颜色是离开色块一段空隙的同色细环，不是贴住色块的粗白环。
7. 卡片底部有分隔线和「重置为默认」。

## 行为

1. 助理信息里的大头像是「编辑头像」。点开后出现头像页；「返回」「完成」、点遮罩或 Escape 都只关闭页面。形状、颜色和照片在点选时就通过现有 `puck.update` 保存。
2. 形状三行的列数固定为 4、4、5，颜色两行固定为 6、5。窄屏可以滚动，不能改列数。
3. 「重置为默认」把形状和颜色写回 `deriveAvatar(assistantId)`，并去掉已保存的 `image`。没有改动时不发请求。
4. 「上传」使用现有头像 `image` 字段。只接受 PNG、JPEG、WebP。浏览器把超过字段上限（262144 字符）的图片缩小成 JPEG 后再提交。非法类型或无法缩小时报错，不写入。改形状或颜色仍保留已有照片。
5. 「生成」只展示说明。Puck 没有头像生成接口，这个页签不发起请求，也不伪造生成结果。

## 不变量

1. 侧边栏、对话和信息栏里的普通头像仍然不画选中环，也没有存在光环。
2. 已保存的非选项形状 id、`black` 和 `#rrggbb` 仍按 0147 归一。照片仍只接受 https URL 或 png/jpeg/webp data URI。
3. 头像更新失败时恢复点选前的头像，并显示已有错误提示。

## 验收

1. 形状 DOM 与样式都是 4 + 4 + 5，颜色是 6 + 5；390px 与更宽的桌面宽度都不折成别的行。
2. 头像页能看到「生成」「上传」和「重置为默认」。重置后的请求体是该助理的默认形状和颜色，且没有 `image`。
3. 合法小图上传后，`puck.update` 带上 data URI，预览改为照片。生成页签不产生 `puck.update`。
4. 选中颜色的环是 `#656569` 细环。`npm run build` 通过。
