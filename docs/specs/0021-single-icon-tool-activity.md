# 0021：每回合一个图标折叠全部工具活动

- 状态：Implemented（用户于 2026-10-05 明确要求设计后直接开发；自动测试已通过，物理手机待验）。
- 来源：0015 虽隐藏了工具详情，却给每个相邻调用组留下一条摘要；大会话仍充满“已处理 N 项”记录。
- 范围：Web 会话正文的手机与桌面共用渲染；不改 Adapter 归类、owner、协议、分页或审批语义。本规格覆盖 0015 的活动组控制外观与展开范围。

## 输入与行为

1. 一个 turn 中所有已验证的 `activity` item 默认都不渲染名称、状态、详情、逐组摘要或占位卡片；不管活动被 Codex 正文分成多少段，只在该 turn 第一条活动原本出现的位置放一个紧凑的“打开工具调用”图标按钮。按钮的 accessible name 与 title 写明操作及当前已加载数量，`aria-expanded=false`。没有活动的 turn 不出现按钮。
2. 点击、Enter 或 Space 激活该按钮，一次展开本 turn 当前已加载的所有活动；每段活动仍按与正文交错的原顺序显示。按钮变为“收起工具调用”，`aria-expanded=true`；再次激活后所有活动隐藏。分页加载旧 item 或实时追加 item 后，当前展开状态保持，新活动并入同一个控制；切换会话或 turn 身份后默认折叠。
3. 运行中的最后一个可见阶段是工具活动时，保留一行“处理中…”状态；该文字不是已完成活动日志，也不要求先展开才能看到。没有可见活动阶段时用“思考中…”。结束、断线、待审批时状态行消失；审批卡不受折叠影响。
4. 旧 Agent 未分类与真正未知的系统消息继续作为兼容性提示显示，不根据字符串猜测为工具活动。展开的详情继续纯文本、有界、不可执行。旧页未加载的调用不计入图标的数量，已有分页入口保持可见。
5. 图标按钮有不少于 44×44 CSS px 的触控区域、明显的键盘焦点和深色背景上的可辨对比；折叠不改变发送状态与阅读锚点，不自动滚到底部。

## 错误与验收

- 页面仍以 owner 提供的 item ID/order 为准；暂缺详情不应导致展开时其他正文丢失。调用详情缺失时保留 0015 的说明。分页失败时保留已加载活动和原错误提示。
- 先写失败的 Web 测试：同一 turn 多组活动默认只出现一个图标、没有任何活动正文；点击后按原交错顺序出现、再次点击全部隐藏；键盘语义、实时追加、分页／不同 turn 隔离、审批和运行状态不回退。再实现并运行 Web 全量测试、构建与浏览器验收。
