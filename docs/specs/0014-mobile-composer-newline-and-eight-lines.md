# 0014：手机输入框回车换行与八行自适应

- 状态：Draft（待用户确认）。
- 来源：2026-10-05 用户要求手机键盘 Enter 只换行、发送必须点击蓝色按钮；输入框默认一行，随内容增长，最多显示八行，超出后在框内滚动。
- 范围：已连接会话页宽度不超过 800px 时的消息输入框及发送交互；不改变 Relay／Agent 协议、消息内容或宽屏快捷键。
- 与既有规格的关系：本规格获批后，覆盖 [0011](0011-compact-mobile-conversation-header.md) 中“手机 Enter 发送、Shift+Enter 换行”和“输入框增高至约四行”的两项要求。0011 的其他布局、触控和 safe area 要求继续有效。

## 输入、输出与行为

1. 手机输入框聚焦时，软键盘或外接键盘的 Enter／Return 只在草稿光标处插入换行，不发起 `turn.start`。Shift+Enter 也只换行。中文等 IME 组合输入中的确认键不得意外发送消息。键盘呈现换行语义，而非暗示 Enter 可以发送。
2. 手机端发送消息必须显式点击／轻点现有蓝色“发送”按钮。点击一次至多发出一次 `turn.start`；空白草稿、未就绪或发送进行中继续遵守现有禁用规则。发送成功后清空草稿；发送失败时保留原草稿及其换行。停止按钮与审批卡片操作不受影响。
3. 手机输入框空白或只有一行内容时，文本区域只显示一行；外围胶囊及按钮仍满足至少 44px 的触控高度。显式换行或自动折行使内容增加时，文本区域随可见内容增长，最多显示八个视觉行（包含自动折行，不只是八个 `\n`）。删除内容或成功发送后应缩回相应行数。
4. 超过八个视觉行后不截断草稿，输入框高度保持八行上限；上下滚动发生在输入框内部，光标移动与继续输入时仍能看到当前位置。发送时提交完整草稿，包括超过八行的部分。输入框不能把整页或对话区撑出视口。
5. 手机软键盘弹出、横竖屏切换和 iOS safe area 下，输入框、发送按钮及错误提示继续可见可操作；高度变化不得遮盖对话末尾或造成页面横向溢出。
6. 宽度大于 800px 的桌面输入仍按现有行为工作：Enter 发送，Shift+Enter 换行；本规格不批准 [0012](0012-compact-desktop-conversation.md) 的其他桌面布局变更。视口跨越断点时，不因重新布局自动发送或丢失草稿。

## 边界与错误处理

- 草稿中的连续空行、长单词／路径、粘贴多行文本都按实际视觉折行计入八行上限；内容始终可编辑、可选择、可滚动。
- 若会话不可发送（例如未选择会话、Agent 不就绪），Enter 仍不得成为手机端的隐式发送路径；现有发送按钮禁用和错误反馈保持一致。
- 高度计算不能只依赖某个浏览器尚未普遍支持的 CSS 特性；目标手机浏览器不支持该特性时也必须满足单行、八行上限与内部滚动。

## TDD 与验收

1. 先写失败的行为测试：手机 Enter／Shift+Enter／IME 不调用发送；按钮点击才发送一次；桌面 Enter 仍发送；失败保留多行草稿，成功清空。
2. 先写失败的尺寸测试：空草稿一行，显式换行和自动折行逐步增长，八行封顶，超出后内部滚动，删除及发送后缩回；按钮触控区域不小于 44px。
3. 实现至测试通过并重构后，运行 Web 全量测试、构建和相关回归测试。
4. 在真实浏览器分别以手机宽度和桌面宽度检查键盘行为、逐行增长、超过八行后的内部滚动、软键盘和错误提示；物理手机再验收键盘实际触感与可用空间。桌面模拟不能替代物理手机验收。
