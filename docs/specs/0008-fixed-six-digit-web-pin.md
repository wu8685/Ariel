# 0008：固定 6 位 Web 连接码

- 状态：Approved，用户于 2026-10-04 确认按此规格进入 TDD。
- 来源：用户于 2026-10-04 要求手机端使用长期固定的 6 位数字 token，而非长随机口令或一次性配对码。
- 范围：可信局域网内 Web → Relay 的鉴别与输入体验；不改变 Codex Desktop 的执行权限，也不把 Relay 开放到公网。

## 输入、输出与安全边界

- Relay 配置保留高熵的 `ARIEL_TOKEN`，仅用于 Desktop Agent 鉴别；新增 `ARIEL_WEB_PIN`，必须恰好为 6 个 ASCII 数字，供手机 Web 鉴别。Web 不能用 Agent 口令代替 PIN，Agent 不能用 PIN 注册。两者均不得进入 URL、HTTP 响应、日志或仓库文件。
- 手机连接页以“6 位连接码”标识，使用数字键盘；输入内容仍只留在当前页面内存。刷新页面需重新输入固定 PIN；同页 WebSocket 重连继续使用内存中的 PIN。不增设持久 cookie、localStorage 或服务端会话库。
- PIN 不设时间到期、不因一次成功失效；Relay 重启后同一配置值仍有效。用户自行在本地配置中保管 PIN，不提交到仓库。
- Relay 对 Web PIN 采用常量时间比较。单个 Relay 进程累计 10 次错误 Web PIN 后，拒绝新的 Web 鉴别直到进程重启；已连接的 Web 与 Agent 不因错误尝试被强制断开。错误次数不对外公布，不记录 PIN 值。Agent 鉴别独立，不消耗 Web PIN 的尝试次数。
- 6 位 PIN 最多只有一百万种组合，且现有 HTTP/WS 局域网传输未加密；错误次数限制只降低在线猜测风险，不能防止同网段窃听。此模式只允许在用户确认的可信局域网使用，不提供公网部署保证。更高安全需求仍需 TLS／正式配对方案。

## 错误与兼容性

- 缺少或格式错误的 `ARIEL_WEB_PIN` 时 Relay 启动失败并指出配置字段；PIN 不应出现在错误文本。`ARIEL_TOKEN` 仍必须为非空 Agent 口令。
- 错误 PIN、错误 role 或锁定状态均不得获得 `hello.ok` 或设备／会话数据；Web 给出连接失败提示，不自动无限快速重试错误凭据。
- 0003 中“Web 与 Agent 使用同一 token”的约定由本规格替代；v1 `hello` 帧字段名 `token` 保持不变，以免扩大协议改动，Relay 按 role 选择对应凭据。

## TDD 与验收

1. 先写 Relay 配置正反例：6 位、前导零、非数字、长度错误、缺失；运行到 red，再实现校验。
2. 先写 Web／Agent 不同凭据、互相不能冒用、错误计数与第 10 次锁定、重启重置的失败测试，再实现鉴别。
3. 先写 Web 输入属性和连接状态测试，再改连接页文案与数字输入体验；Web 全量测试与构建通过。
4. 使用隔离 fixture 和真实手机：6 位 PIN 登录、旧会话自动加载、发送、停止、待处理交互、切后台恢复；不向业务会话注入测试消息。只在当前可信局域网临时启动服务，结束关闭。
