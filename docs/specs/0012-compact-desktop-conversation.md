# 0012：电脑浏览器紧凑会话布局

- 状态：Implemented（2026-10-08；侧栏顶部已压缩为三层紧凑结构，桌面与移动 Chromium 的会话列表起点均在 `190px` 内；自动测试、截图与生产构建已验；物理设备保留用户复验）。
- 来源：用户要求电脑浏览器也沿用手机端的紧凑设计，尽量用 icon 缩小非必要 header 和控件，把更多面积让给对话内容。
- 范围：宽度大于 800px 的已连接 Ariel Web 会话页。沿用 [0011 手机紧凑布局](0011-compact-mobile-conversation-header.md)的 Night 视觉、权限警示与交互语义；不修改 Relay／Agent、会话数据或手机布局。

## 现状与目标

- 当前 841×864 实际浏览器中，常驻侧栏宽 312px，品牌栏高 70px，会话标题区高 116px；显示连接通知时，输入区高 229px，对话滚动区仅 529×449px。标题和状态在多个区域重复占位。
- 目标是在会话选定、无通知且空草稿的稳定状态下，电脑端也只保留约 64–72px 的顶部会话栏及约 60–72px 的底部单行输入区。侧栏默认不占用会话宽度，按需覆盖展开。1280×720 下对话滚动区高度至少 570px；841×864 下至少 710px。正文仍保持适宜阅读的最大行宽，不把长段文字拉满超宽屏幕。
- 保持近黑连续画布、白字、灰色次要信息与蓝色操作高亮；灰色 logo、琥珀色权限风险提示和现有焦点样式不改变语义。

## 输入、输出与行为

1. 已连接的电脑会话页不再显示独立 Ariel／Relay 品牌栏。logo、完整 Relay 状态与“断开”入口保留在侧栏顶部。连接前的登录页仍显示品牌、连接状态、错误说明及连接码输入，不因本规格减少必要信息。
2. 会话页顶部是一行紧凑工具栏：左侧菜单按钮，中间单行省略的会话标题与工作目录，右侧权限信息 icon；不再单独显示 `CODEX SESSION` 装饰标签、常驻权限文字条或独立占高的运行状态行。Relay 连接状态由菜单按钮上的状态点及可访问名称表达。会话运行／加载状态仍在正文或现有交互状态中可辨识，不能因缩头部误导为“已完成”。
3. 电脑端侧栏改为抽屉：会话选定后默认收起，不占主内容宽度；点击菜单按钮展开，点击遮罩空白处或按 Escape 收起，点击侧栏内部不误收起；选中会话后收起。尚未选择会话时可显示侧栏供选择。抽屉宽度保持适宜浏览会话列表，窄电脑窗口不得造成页面横向溢出。
4. 权限信息沿用手机端的可点击 icon 与浮层：点击显示 Desktop sandbox、approval policy 与完整风险警示，再点、点外部或 Escape 关闭。`Full Access`／状态未知时 icon 持续为琥珀警示色；普通权限为中性色。浮层不能撑高 header 或被窗口边缘裁切；键盘聚焦可读。真实审批卡片仍在正文中，不能并入权限浮层。
5. 电脑端输入区沿用手机端的炭灰色圆角胶囊：空草稿单行，输入多行增长至约四行后仅内部滚动；发送使用带可访问名称的 icon 按钮，停止操作仅在运行中出现且保持清楚可辨。Enter 发送、Shift+Enter 换行、草稿保留、禁用状态及错误通知语义不变。键盘提示可移入按钮 tooltip／可访问描述，不占常驻一行。
6. 菜单、权限、二维码登录、断开、刷新、新建会话、关闭、搜索清空、队列引导／删除／更多、附件、取消编辑、停止和发送等纯功能入口统一使用内联 SVG icon，不显示重复的常驻文字。每个入口必须保留明确的 `aria-label`，并在支持 hover 的精细指针设备上显示同义 tooltip；手机触控端不依赖 tooltip 才能理解关键流程。
7. 登录、创建、审批、危险确认、历史分页和异常恢复等需要用户理解后果的语义型操作继续保留文字，不为了“全 icon”牺牲可理解性。icon 不使用 Emoji 或字体字符，不引入第三方图标依赖，保持统一的线宽、圆角端点和 `currentColor` 主题适配。
8. icon 操作入口维持至少 36×36px 的视觉尺寸；会话菜单、权限等主要入口保持至少 40×40px 的点击区域，并提供清晰 hover／focus／disabled 状态。长标题、目录、路径和代码不能遮挡按钮或产生页面级横向滚动。桌面窗口缩放到 801px 附近与手机断点切换时，布局和菜单状态连续可用。
9. 本规格不增加语音等新能力；不改变消息正文、原会话状态、审批语义或安全边界。
10. composer 与排队 work item 的外层容器必须共用同一个圆角设计 token；基准值为现有排队 work item 的 `16px`。桌面端与手机端不得分别硬编码不同半径，后续调整必须同时生效。
11. 会话抽屉顶部不得重复堆叠品牌、会话标题、设备标签和设备状态说明。品牌、连接状态与会话操作合并为一行紧凑工具栏；设备选择合并为一行，并以状态点和可访问名称表达 Agent／Desktop readiness；搜索与统计保持紧凑。扫码登录、断开、新建、关闭和刷新能力继续可用，不能通过删除功能换取空间。390×844 与 1280×720 下，会话列表容器顶部距离抽屉顶部不得超过 `190px`。

## 错误与边界

- Relay／Agent 断线、未选择会话和权限未知时，连接状态、错误或警示仍可发现；不能为了缩小组件而隐藏必要提示。
- 通知出现或草稿变长时，输入区可按内容增高，但不得覆盖会话正文，正文应继续滚动；上述目标高度只对无通知、空草稿的稳定状态适用。
- 极窄电脑窗口与高缩放场景若无法同时容纳标题、目录和按钮，优先省略文字，不缩小主要点击目标。

## TDD 与验收

1. 先写失败的 Web 测试：已连接桌面端品牌／状态／断开位于抽屉，菜单按钮可用；选会话、遮罩、Escape 和侧栏内部点击行为；登录页信息仍保留。
2. 先写失败的权限与输入区测试：权限浮层／警示色／审批卡片、单行与多行草稿、发送／停止以及可访问名称均保持正确；再实施最小 DOM／CSS 调整。
3. 先写失败的 icon 契约测试：纯功能入口没有可见文字，包含装饰性 SVG、保留可访问名称和 hover tooltip；语义型操作仍保留文字。
4. 增加可重复的浏览器级布局回归，至少覆盖 1280×720 和 390×844：量测 header、对话滚动区、输入区与侧栏占位；验证无横向溢出、tooltip、权限浮层和抽屉可操作。手机端 0011 的布局结果不得退化。
5. Web 测试、构建与 Go 回归通过；在真实 Relay／隔离会话的浏览器中人工检查 Night 视觉、长标题、正文、通知、抽屉、权限和输入状态。浏览器验收不对业务会话发送消息。
6. 样式契约测试必须确认 queue panel 与 composer 引用同一个圆角 token；1280×720 桌面与 390×844 移动 Chromium 必须分别断言两者的计算圆角均为 `16px`，并更新截图基线进行视觉复核。
7. 先写失败的侧栏 DOM、样式与浏览器几何测试：不得保留独立“会话”标题、可见“设备”标签或独占一行的设备状态说明；紧凑工具栏中的全部操作保留可访问名称；桌面与移动 Chromium 均断言会话列表在 `190px` 内开始，并以截图复核功能密度和可读性。

## 实现结果

- 已连接页面在桌面和手机上共用 66px 紧凑 Header、覆盖式会话抽屉、权限信息弹层、圆角双层 composer 与统一的 14px 输入字号；桌面侧栏不再常驻占用对话宽度。
- 纯功能入口统一为内联 SVG icon，并以 `aria-label` 和仅在精细指针 hover／键盘 focus 时显示的 tooltip 说明含义。登录、审批、创建、历史分页等语义型操作继续保留文字。
- composer 在两端都从 44px 单行开始，最多增长到八行后内部滚动；发送、停止、附件与取消编辑均使用 36px 圆形 icon 控件。
- composer 与排队 work item 的外层容器统一引用 `--radius-work-item: 16px`，桌面端与手机端不再维护各自的硬编码圆角。
- 会话抽屉将原品牌状态、会话标题操作、设备标签状态和搜索统计压缩为品牌操作工具栏、设备选择、搜索三层；统计下沉到紧邻列表的轻量标题。连接与 Agent readiness 使用状态点和可访问名称表达，所有原操作保持可用，会话列表在桌面与移动测试视口中均于 `190px` 内开始。
- 桌面隔离 fixture 验证了全宽对话、抽屉遮罩、权限入口、tooltip 和 icon-only 队列／composer；既有移动端截图基线已逐张复核并更新。完整证据见[0012 验收记录](../testing/2026-10-08-0012-unified-responsive-icon-ui.md)。
