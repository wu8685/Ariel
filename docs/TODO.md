## 2026-10-03 进展

历史跨页读取、原会话 ID 校验、owner 发现、快照与真实 patch 合并、fixture 发送及精确停止已有通过证据，见 [兼容性报告](compatibility/2026-10-03-m0.md)。未加载历史的独立 OS deep link 也在隔离 fixture 上完成“打开 → 原 owner → 发送/停止”实测；Agent/Web 自动触发及焦点、升级等回归仍未实现，必做 TODO 保持未完成。按待办约定，未经用户确认不勾选完成。

补充回答串行链路已实测通过：两个问题、选项和自由文本、canonical history 精确回显、独立持久化完成核对、完成后本地拒绝重放。双客户端不同答案竞争也已实测：两个 IPC 回执均为 `ok`，只有第二客户端的答案得到精确回显；回执不能直接映射为“回答成功”。中断后过期请求的本地拒绝和 exact turn 持久化中断亦已验证；原生服务端对过期回答的处理不作为产品保证。

用户已确认审批语义。当前版本的 command cancel 隔离实测使原 turn 中断，独立历史确认；公开历史未保存嵌套 command item。命令允许、文件与权限审批仍待验证。

忙时发送实测发现：第二客户端仍收到 accepted，且返回当前 turnId；立即停止后未见第二条消息持久化。这不足以判断是否排队，但足以证明 Agent 不能把 native 回执当作“新 turn 已受理”。M2 需做 thread 级串行入口，并在锁内读取 live idle 状态。

## 2026-10-04 进展与剩余验收

Relay、真实 Desktop Agent、Mock Agent 和响应式 Web 已落地。Web 点选未加载的真实历史 fixture 后，可自动让 Desktop 打开同一 thread 并取得原 owner；同一 fixture 的发送、实时更新和精确停止已走完整 Web→Relay→Agent→Desktop 链路。命令允许与拒绝并停止、文件变更允许与拒绝、多问题补充回答也已在独立 fixture 中验证；文件允许后实际生成目标文件，拒绝后未生成。相关规格、单测、兼容性证据和运行说明均在本仓库。

断线保留选择与草稿、重新订阅、Desktop IPC 健康检查、会话列表轻量化、超大历史显式错误已实现，真实浏览器中复验了 Relay／Agent 重启后恢复。发送后还会核对原 owner 中 `userMessage.clientId` 与本次提交 ID、turnId、文本一致；这一字段关系已在隔离 fixture 实测。单元／竞态测试与具体限制见 [M1–M4 测试记录](testing/2026-10-04-m1-m4.md)。未完成的验收重点：① 当前 Codex `request_permissions_tool` 为关闭状态，真实权限请求无法在本机生成；② 真正的手机设备访问尚未验收；③ Desktop 进程退出与重启不能在不影响用户业务会话的情况下直接做破坏性实测；④ 外部 Desktop 与 Ariel 精确同时发起 turn 的真实压测仍未做，竞态结果缺证据时按 unknown 处理。所有待办继续保持未勾选，完成须先经用户确认。
